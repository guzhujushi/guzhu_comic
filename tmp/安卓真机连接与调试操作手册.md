## 1. 三层前提，别混

| 层 | 是什么 | 在哪 | 手机侧要做什么 |
|---|---|---|---|
| ① 构建 | JDK + Gradle + Android SDK + Chaquopy，把 `backend/` + `frontend/dist` 打成 APK | **PC** | 什么都不用做 |
| ② 连接 / 调试 | `adb`：装包、看日志、`chrome://inspect` 调 WebView | PC ↔ 设备（USB / 无线 / 模拟器） | USB 调试打开即可，**不装 sshd、不需要 root** |
| ③ 运行 | 真跑：图源连通、长图渲染、后台下载 | 设备 | 提供设备（模拟器也行，见 §6） |

## 2. 一台手机能不能当测试机

**合格**：系统能装 APK（Android / EMUI / 带 AOSP 兼容层的 HarmonyOS 4 系）、**API 26+**（Android 8.0+）、
CPU **arm64-v8a**、能开 USB 调试、空闲存储 ≥ 2 GB、允许装未知来源。
建议先用**较旧/较弱**那台验收，主力机留到最后试手感。

**不合格**：**纯血鸿蒙 HarmonyOS 5 / 6（NEXT 系）** —— 调试走 `hdc` 不走 `adb`，通常也不吃 APK；x86 / 32 位机（没有 `curl_cffi` 轮子）；iOS。

**插线一眼看**：设备管理器里出现 **`ADB Interface` / `ADB Device`** = 有戏；只出现 `HDC Device` = 华为鸿蒙线。
最终判定只看两件事：`adb devices` 认不认它，以及 APK 装不装得上。

## 3. 一次性准备

**PC 侧**（都已就绪，记下来备查）：

| 项 | 说明 |
|---|---|
| JDK | **用 Android Studio 自带的 JBR 25.0.3**（系统 JDK 26 太新，Gradle 9.8.1 跑不动）；`scripts\build_android.ps1` 已经自动把 `JAVA_HOME` 指过去 |
| Python（构建机） | Chaquopy 要求与 app 同 minor → **必须 3.13**；`android/gradle.properties` 里的 `guzhu.buildPython` 指向它 |
| 代理 | `dl.google.com` 一般直连；Chaquopy 的 pip 仓库（`chaquo.com`）不稳 → 给 Gradle 配本机 7890 代理 |
| 仓库里的 `.ps1` | 一律 **UTF-8 带 BOM + LF**（PowerShell 5.1 读无 BOM 的 `.ps1` 会按 ANSI 解，中文直接把脚本撕成语法错误） |
| 工作区 | Android Studio **Open 仓库里的 `android/` 这一层**（不是仓库根）；`local.properties` 由 AS 首开生成，别入库 |

**手机侧**：① 「关于手机」连点版本号 7 次开开发者选项 → ② 打 **USB 调试**（国产 ROM 可能还要开「USB 调试（安全设置）」
/「USB 安装」，有的要登录厂商账号）→ ③ 插线时选**传输文件（MTP）**（只选"仅充电"时 PC 什么都看不到）
→ ④ 可选：Android 11+ 的**无线调试**（`adb pair` + `adb connect`）。

## 4. 连上以后先跑这几条

```powershell
$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
& $adb devices -l                                  # 期望 device（不是 unauthorized / offline）
& $adb shell getprop ro.product.model              # 型号
& $adb shell getprop ro.product.cpu.abi            # 期望 arm64-v8a（模拟器是 x86_64）
& $adb shell getprop ro.build.version.sdk          # 期望 >= 26
& $adb shell getprop ro.build.version.release      # 系统版本
```

全过 = 这台能进真机验收。

## 5. 装包 / 调试 / 日志

```powershell
# 装（换签名要先卸：& $adb uninstall cn.guzhujushi.comic）
& $adb install -r android\app\build\outputs\apk\full\release\app-full-release.apk
& $adb shell am start -n cn.guzhujushi.comic/cn.guzhujushi.comic.MainActivity

# 启动链路（壳 + Python 两侧）
& $adb logcat -s GuzhuShell:* python.stdout:* python.stderr:* AndroidRuntime:E

# 调试页面：壳里开了 WebView 调试 → PC 上用 Chrome 开 chrome://inspect
# 从 PC 看设备里起的那个静态服务（调试用）
& $adb forward tcp:47753 tcp:47753
```

- **MTP 侧载**也能装：把 APK 拖进手机的 `Download/` → 文件管理器点它（要允许未知来源）。这条路不需要 `adb`，但看不到日志。
- **截图必须走 `cmd`**：`cmd /c ""$adb" exec-out screencap -p > 文件"` —— PowerShell 直接 `>` 会把 `\n` 变成 `\r\n`，PNG 当场损坏。
- `run-as <包名> ...` 能读 app 私有目录里的文件（**只有 debuggable 的调试包可以**，release 包不行）。

## 6. 模拟器这条路（当前主力，0 元）

前提：`emulator.exe` + x86_64 镜像已装、AVD `guzhu_x86` 已建。

```powershell
# 1) 起模拟器（WHPX 硬件加速，本机约 60 秒）
& "$env:LOCALAPPDATA\Android\Sdk\emulator\emulator.exe" -avd guzhu_x86
& $adb devices                        # emulator-5554  device

# 2) 出包：full（arm64 真机版，能在模拟器跑）或 ui（x86_64 轻量版，验不了图源）
powershell -ExecutionPolicy Bypass -File scripts\build_android.ps1 :app:assembleFullDebug
& $adb install -r android\app\build\outputs\apk\full\debug\app-full-debug.apk

# 3) 触屏链路：点屏幕 / 返回键
& $adb shell input tap 84 295
& $adb shell input keyevent KEYCODE_BACK

# 4) 依赖探针（壳里带的开关，**不在正常启动路径上**）
& $adb logcat -c
& $adb shell am start -n cn.guzhujushi.comic/cn.guzhujushi.comic.MainActivity --ez guzhu.probe true
Start-Sleep -Seconds 60                       # 含真网络请求，全程约 12~60s
& $adb logcat -d -v time -s python.stdout:* GuzhuShell:* | Out-File tmp\_probe_run.log -Encoding utf8
```

- **`ui` 变体**（`assembleUiDebug`，包名带 `.ui` 后缀，能和 `full` 同时装）只跑 x86_64、**故意不带 `curl_cffi`**
  （x86_64 上没有它的安卓轮子，`src/ui/python/curl_cffi/` 是个一调就抛的桩）→ 它**永远验不了图源连通**。
- **arm64 的 `full` 包照样能装进 x86_64 模拟器**：这代模拟器自带 ARM 翻译层
  （`ro.dalvik.vm.native.bridge = libndk_translation.so`、`abilist = x86_64,arm64-v8a`）。
  **T1 / T1-b / T2 就是靠这条关闭的**（探针 11 步结果见 `tmp/安卓端技术栈与现状.md` §5）。
- **翻译层不能拿来测性能**（只有 arm64 → x86_64 一个方向，速度也不是真机基线）：手感 / 内存 / 保活仍要真机（T3~T6）。

## 7. 排障表

| 现象 | 大概原因 | 怎么办 |
|---|---|---|
| `adb devices` 空的 | 没开 USB 调试 / 只选了"仅充电" / 线只能充电 / 驱动没装 | 逐条查：开发者选项 → 弹窗选"传输文件" → 换线 → 装厂商驱动 |
| 状态 `unauthorized` | 手机上没点"允许 USB 调试" | 手机上点允许（勾"始终允许"）；不行就"撤销 USB 调试授权"再插 |
| 状态 `offline` | adb 服务状态乱了 | `adb kill-server` → `adb start-server` |
| 只有 `HDC Device`、没有 ADB 接口 | 华为鸿蒙线（纯血鸿蒙） | 换个能装 APK 的设备；或按用户的实测结论直接试装 |
| `INSTALL_FAILED_NO_MATCHING_ABIS` | 机型 ABI 与包不符 | 我们只出 `arm64-v8a`；先确认设备 ABI |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 签名不一致（debug ↔ release） | `adb uninstall cn.guzhujushi.comic` 再装 |
| 装上了但一打开就崩 | Python 侧缺依赖 / Chaquopy 初始化失败 | 看 `AndroidRuntime` 与 Python stderr |
| 阅读器里一堆裂图 | 图没下来（网络）或解扰没做 | 看 app 日志（下载失败现在会记一行）；探针第 11 步验解扰 |
| 截图打不开 | PowerShell 的 `>` 弄坏了 PNG | 用 `cmd /c "... > 文件"` |
| `sdkmanager` 包名被截断 | PowerShell 把分号当语句分隔符 | 写成 `.bat` 再 `cmd /c` 跑，别在 PS 里拼带分号的参数 |
| 探针跑完只有壳日志 | `python.stdout` 那个 tag 没进过滤 | `-s python.stdout:* GuzhuShell:*` 两个都带 |
