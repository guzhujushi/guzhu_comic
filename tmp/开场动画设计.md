# 开场动画（GuZhu 字标）设计稿

> 目标：点开窗口的第一帧就是「GuZhu」手写动画；动画期间后台把首页要的数据预热好；
> 动画结束字标飞进左上角品牌位，取代那儿单调的「孤竹漫画」，「Guzhu Comic」不动。
>
> 网络做法调研（含来源链接）：`tmp/开场动画调研.md`。实测数字见 §2。

## 0. 结论先行

| 决策 | 选择 | 理由 |
|---|---|---|
| 闪屏放哪 | 写死在 `frontend/index.html` 的**内联** `<style>` + `<div id="splash">` | 这是唯一"早于应用 JS"的位置；放进 `main.ts` 的话，dev 态要先拉一整张模块图，白屏几百 ms |
| 字标怎么画 | 内联 **SVG 单线笔画 path** + `stroke-dashoffset` 描边（主）/ 系统手写体 + mask 露出（备） | 不依赖外链与字体，笔画顺序可控；Apple hello 的公开复刻全是这条路（§5） |
| 怎么落位 | **FLIP**：量首末矩形 → `transform` 反向偏移 → 播放 → 交棒静态 DOM | 零布局抖动；**不用 View Transitions**：文档不可见时它整个跳过，而启动期窗口恰好可能不可见（§6） |
| 预热口径 | 后端并发拉**同一批 cache key**（hero + 各分类 + 推荐段 + 前 N 部详情），封面另外 `new Image()` 热一遍 | 首页照常发请求，只是全部命中缓存（实测 10ms 级），`board.ts` 零改动 |
| 时长 | 描字约 1.1s，最短 1.1s、最长 2.4s；可点一下 / Esc 跳过；`prefers-reduced-motion` 直接跳过 | 动画只负责"遮住冷启动的网络等待"，不许反过来拖慢启动 |
| 窗口底色 | `main.py` 显式传 `background_color="#07080a"` | pywebview 默认 `#FFFFFF`；窗口在导航开始时就 show，闪屏之前的白是它（§3.4） |

## 1. 需求拆解

1. 窗口一出现就播「GuZhu」开场动画（Apple hello 那种"写出来"的感觉）。
2. 动画期间后台预热；动画放完进首页，hero / 分类横条已经是**内容**而不是骨架（追求 Windows 秒开）。
3. 动画结束，字标飞到左上角，落进左侧导航的品牌位。
4. 落位后取代「孤竹漫画」那行，「Guzhu Comic」那行不动。

### 落位（2026-10-14 已定稿：只换「孤竹」）

品牌位两行：`.brand-mark` = 字标 + 「漫画」，`.brand-sub` = 「Guzhu Comic」（这行不动）。

你写的是"代替原本单调的 guzhu 这两个字，comic 不变" —— **2026-10-14 定的是第二种**：只把「孤竹」两字换成字标、
保留「漫画」（品牌行 = `GuZhu漫画`）。已实现：

- `frontend/src/main.ts`：`<span class="brand-mark"><span class="brand-slot">孤竹</span>漫画</span>`
  —— `.brand-slot` 是落点，里面的「孤竹」是兜底文案（没有闪屏那份 SVG 时照旧显示）。
- `frontend/src/splash.ts::placeNavMark()`：只往 `.brand-slot` 里塞克隆体、只清这一格。
- `frontend/src/style.css`：`.brand-mark` 是带 `white-space: nowrap` 的 flex 行 + 新的 `.brand-slot`。

**一处要记的实测**：按"取代整行"做的那版（`.brand-logo` 88px）在 208px 的导航里**塞不下** ——
88px 字标 + 两个字会折成竖排，所以导航里字标收到 **76px**（大写高 ≈ 15px，跟旁边 15px 的「漫画」齐平；
闪屏那份仍是 `min(56vw, 620px)` 不变）。FLIP 量的是实时矩形，改宽度不影响衔接。

## 2. 实测数字（本轮量的）

脚本：`tmp/_bench_home.py`（临时；只把模块级路径指到 `tmp/_bench`，没碰真实用户数据，跑完即删）。

| 场景 | 实测 | 说明 |
|---|---|---|
| 暖缓存：首页 6 个分类元数据串行读 | **9~11 ms** | 假图源；`get_ranking` × 6 全走 `meta_cache` |
| 冷启动：同样 6 个分类（图源 350ms/次、串行） | **~2205 ms** | 纯网络等待 —— 这就是动画要遮的那 1~2 秒 |
| `prefetch_albums(12)` 的调用返回耗时 | **1.2 ms** | "立刻返回 + 后台线程"这条约定是有效的，预热不占桥 |

结论：**"秒开"的敌人只有冷启动那一次的网络等待**；命中缓存后首页元数据是毫秒级的。
所以动画的价值 = 用一个用户愿意看的 1~2 秒，把这笔网络等待挪到幕后。

另外记一笔：dev 态（`main.py` 指向 `http://localhost:5173` + vite 模块图）本身比打包态慢不少，
"真·秒开"的数字要在**打包态**（`frontend/dist`）下测；dev 态测的是功能，不是性能。

## 3. 秒开的三段式

### 3.1 时间轴

```
t=0ms      窗口出现。index.html 的内联闪屏已经在画（不透明暗底 + 居中字标），不是白屏。
t≈0ms      <script type="module"> 开始加载（dev 态这一坨是大头）。
t≈?ms      main.ts 跑起来 → 注册路由 + 铺 nav → bootSplash()（闪屏开始计最短/最长）
t≈?ms      pywebview 就绪 → 立刻发预热：prefetch_home() + prefetch_albums() + 封面 new Image()
t≈?ms      startRouter() 照常跑，首页在闪屏**底下**把 hero 与分类横条铺好
           —— 骨架 → 内容这一整段过程全被闪屏遮住，用户看不到
t=揭幕     揭幕条件 = max(min_ms, 首页铺完) 但不超过 max_ms
           淡出 120ms + FLIP 380ms → 移除 #splash → 露出已经铺好的首页
```

关键点：**闪屏不阻塞路由**。路由照现在的顺序跑（`main.ts` 末尾 `startRouter()`），
闪屏只是盖在上面；这样"揭开即成品"，也顺带避免 hero 的虚化入场在揭幕后重演一次。

### 3.2 闪屏的实现细节

- DOM：`<div id="splash">` 放在 `index.html` 的 `<body>` 最前（`#nav` / `#app` 之前），
  里面只有一块内联 SVG 字标。`position:fixed; inset:0; z-index:100`，自带 `pointer-events`，把底下全挡住。
- 样式：**全部内联**写在这个 div 上的 `<style>` 里（动画关键帧也写进去）。
  注意闪屏期间 `style.css` 还没生效，所以 **`--bg` / `--rail` 这些变量一个都不能用**，
  尺寸颜色一律写字面值。
- 底色：**不透明 `#07080a`**（= 亮着毛玻璃时的画布色也照这个走）。
- 资源：**零外链**（不引字体、不引图片、不引 JS），保证它是稳定的首帧。
- 移除：FLIP 播完 `el.remove()`，同时清掉 `document.documentElement.dataset.splash`
  （给 CSS 留一个"`[data-splash]` 期间不播入场动画"的开关）。

### 3.3 揭幕时机

- `ready` = 首页铺完 或 首次失败（失败也揭，露出的是现有那套错误提示 + 自动重试）。
- 揭幕 = `clamp(max(min_ms, ready), min_ms, max_ms)`；到 `max_ms` 必揭，不许把启动拖在这。
- 桥 5s 超时 / 预热失败：一律不影响揭幕节奏。

### 3.4 窗口底色（"闪一下白"的真正来源）

pywebview 的 `create_window` 默认 `background_color="#FFFFFF"`（**已在本机 6.2.1 的签名里核实**），
而 `main.py` 现在没传这个参数。窗口是 WebView 开始导航时就 show 的，所以"闪白"发生在我们的 HTML 之前 ——
内联闪屏救不了它，得从窗口参数上治：

- `main.py` 显式传 `background_color="#07080a"`。
- **但注意**：`winforms.py:286-292` 里，`transparent=True`（也就是毛玻璃开着）时会走透明分支，
  `background_color` **被忽略**（`DefaultBackgroundColor = Transparent`，Form 的 BackColor 不设）。
  所以 glass 开着时还得靠"首帧足够快"来盖住那一下。
- 兜底（**先别盲改，真机看一眼再定**）：pywebview 支持 `hidden=True` + 后面 `window.show()`，
  把窗口出现推迟到页面首帧之后；代价是"窗口出现"本身变晚，跟"秒开"是笔交易。

## 4. 预热清单（口径）

| 预热项 | 复用谁 | 上限 |
|---|---|---|
| hero + 各分类榜单元数据 | 与 `board.ts` **同一个 cache key** 的 `get_ranking(range, cat, 1, sort)` | 6 次请求 |
| 首页第一段推荐 | `get_recommendations('home')` | 1 次 |
| 前 N 部详情（tag / 作者，留给推荐与详情页） | `prefetch_albums` | `prefetch.albums` = 12 |
| 封面图 | `new Image().src = cover_url` 逐张 | 只热"真的会铺出来"的那些（hero 3 + 每分类前 `--cols` 张 ≈ 20 张） |

**不做**：章节图 —— 闪屏期间用户还没进详情页，不知道要哪一话；进了详情页照现有 `prefetch_chapter` 走。

## 5. 字标怎么画：三条路线

| 路线 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A. SVG 单线 path 描边**（推荐） | 手画 `GuZhu` 的**单线笔画**路径，`fill:none` + `stroke-linecap:round`，`pathLength="1"` 归一化后 `stroke-dashoffset` 从 1 → 0 | 跨机器一致（不靠字体）；可按笔画分组依次下笔（G→u→Z→h→u）；结束时能留 stroke，也能换成填充体 | 得把 5 个字母的路径描出来（我来；手感要你看过真机再定稿） |
| **B. 系统手写体 + mask 露出** | `font-family:'Gabriola','Ink Free','Segoe Script',cursive`，文字铺好，一条渐变 mask 从左扫到右 | 零描路径成本，字形现成好看 | "露出" ≠ "写出"，没有笔尖移动的质感；标准 `mask-image` 要 Chromium 120+，老 Runtime 得加 `-webkit-` 前缀 |
| C. 纯淡入/缩放 | 最省事 | 一行 CSS | 最不像 hello |

两个必须知道的坑（调研结论，已复核来源）：

- **普通字体转出来的 path 不能用**：那是字形**轮廓**，一个字母常是多条闭合路径（`o`、`e` 内外两圈），
  跑描边会变成"先描外圈再描内圈"，"一笔写完"不成立。要单线观感只能**手画 path** 或用单线笔画字体（Hershey）。
- **B 路线的字体本机都在**：我扫了 `C:\Windows\Fonts`（571 个），
  `Gabriola.ttf`（最像书法）、`Inkfree.ttf`（最像随手写）、`segoesc.ttf`（Segoe Script，连笔）都在。
  注意 `MISTRAL.TTF` / `FRSCRIPT.TTF` 这类是靠装 Office 带进来的，**不能当"Windows 自带"依赖**。
  另外系统字体不能打进安装包，真要随包分发就换 OFL 字体（Caveat / Dancing Script / Great Vibes）。

建议：**A 打底，B 留成 `splash.style: font` 的开关** —— 万一 A 的描字手感你不满意，切一下就有对比。

### 5.1 定稿参数（2026-10-14 二稿）

一稿（笔画 14 / viewBox `0 0 590 240` / 闪屏 460px）真机看过之后被指出：笔画太细、`u` 太瘦、边缘碎片化、字太小。二稿：

| 项 | 一稿 | 二稿 |
|---|---|---|
| 笔画宽 | 14 | 25 |
| viewBox | `0 0 590 240`（字只占 74% × 49%） | `23 45 637 161`（紧贴字身，四周 4.5） |
| 闪屏宽度 | `min(46vw, 460px)` | `min(56vw, 620px)` |
| 导航字标 | 70px | 88px（2026-10-14 落位定稿后收窄到 76px，见 §1） |
| `u` 碗宽 / x 高 | 0.48 | 0.65（与 `h` 的肩膀同宽） |

几何坐标系：笔画 25、大写顶中心 y=62、x 高顶中心 y=100、基线中心 y=189。
"碎片化"是两处几何没对齐：`u` 的碗底两段 `Q` 不切（看着有折角）；`h` 的肩膀起点比竖线中心线偏左 3 个单位（圆头探出个小疙瘩）。二稿把 `u` 的碗改成一个半圆的三次贝塞尔（控制点 `r·4/3`），`h` 的肩膀终点落在竖线中心线上（圆头被竖线盖住）。

### 5.2 三稿：斜体 + 放慢（2026-10-14）

- **斜体 14°，烙进坐标**：整条字标绕基线斜切（`x' = x + (189 - y)·tan14°`）。斜切对直线 / 三次贝塞尔是精确的，对 `A` 圆弧不是（圆会变成椭圆），所以先把 G 的 250° 弧、h 的 180° 肩膀换成三次贝塞尔再切 —— **现在路径里一个 `A` 都没有，别改回去**。
- **不吃系统字体**：装到哪台机器都是这副样子。手写体那条路（`Segoe Script` / `Segoe Print` / `Ink Free` / `Lucida Handwriting`，本机都验过，效果见 `tmp/_ui/hand.png`）可行，但要放弃逐笔描字、改成 mask 扫过，字宽还随字体走 —— 先不做。
- **放慢**：描字 1000 → 1500ms，停留 300 → 450ms（最短 1950ms），硬揭 2400 → 3000ms。
- viewBox 随之变成 `37 45 645 161`，闪屏宽度仍 `min(56vw, 620px)`，导航 76px（原 88px，落位定稿后收窄，见 §1）。

## 6. FLIP 落位

1. 揭幕那一刻，测量字标当前矩形 `first = markEl.getBoundingClientRect()`。
2. 目标矩形 = 导航品牌位里装字标的那一格（`.brand-slot`）。目标位此刻先 `visibility:hidden` 占着位置，量出 `last`。
3. `transform: translate(dx,dy) scale(s)`（`transform-origin: top left`），
   `transition: transform 380ms cubic-bezier(.22,.61,.36,1)`（或 `el.animate()`）。
4. 播完：`#splash` 整个移除，`.brand-slot` 的内容换成**静态字标**（inline SVG，76px），
   旁边的「漫画」与下面 `Guzhu Comic` 那行都不动。
5. 红线：落位期间目标位保持 `visibility:hidden`，不让"两个 GuZhu"同框。
6. 落位后**没有任何循环动画**，导航里就是一份静态 SVG，跟 hover / 毛玻璃都不打架。
7. 兜底：换文案那一步失败（SVG 没插进去）就保持原来那行「孤竹漫画」—— 导航不会因为闪屏出问题而空掉。

**为什么不用 View Transitions**：MDN 写得很明确 —— `document.startViewTransition()` 调用期间
若文档处于 `hidden`（窗口被遮挡 / 最小化 / 另一个标签在前），**整个过渡会被跳过**；
而 pywebview 启动期正好可能"先 hidden 再 show"，字标飞入恰恰发生在那一刻。
FLIP 不受这条限制（Chromium 团队 Paul Lewis 的原始文章，链接见 §13）。

## 7. 时长、跳过、降级

- 描字动画本身约 **1.1s**（`min_ms` 默认 1100 就是它的地板）；`max_ms` 默认 **2400**（到点必揭）。
- 收尾 120ms 淡出 + 380ms FLIP ≈ 0.5s，算动画不算等待。
- **可跳过**：动画期间点一下 / 按 Esc 直接揭幕（Apple HIG 的 Motion 章节要求动效可跳过 / 可取消）。
- `prefers-reduced-motion: reduce`：不描字、不 FLIP，闪屏只做 200ms 淡入淡出，预热照跑。
- 每次开窗都播（要的是仪式感）；"24h 内只播短的"这类**默认不做**。
- 参考量级（一手来源，见 §13）：Android 官方建议闪屏动画 ≤ 1000 ms、NN/g 的 1 s 档、web.dev 的 FCP 优秀线 1.8 s。
  → 我们的 1.1s 描字 + 0.5s 收尾正好落在这几档附近，不再往上加。

## 8. 接口与代码接缝

- 后端新增 `prefetch_home(range, sort)`：立刻返回，后台 `ThreadPoolExecutor(4)` 并发把 §4 前两行打掉。
  风格照 `prefetch_albums`（fire-and-forget）。**必须复用同一套 cache key**（`ranking:{range}:{cat}:{order}:1`），
  否则首页后面那次请求还是走网络，白预热。
- 前端新增 `frontend/src/splash.ts`：`bootSplash()` / `splashReady()` / `dismissSplash()` 三个出口，自己管最短/最长定时器。
- `main.ts`：`bootSplash()` 放最前；`startRouter()` 照旧，**不 await 闪屏**。
- `board.ts`：首屏拿到内容（或首次失败）时调一次 `splashReady()`。
- 预热用的 `range/sort` 从 `board.ts` 导出一个读 prefs 的小函数来拿，别在两处各读一遍 localStorage。
- `main.py`：`create_window(..., background_color="#07080a")`（见 §3.4）。
- `frontend/src/pywebview.d.ts` 同步加 `prefetch_home`。
- 品牌位照旧先铺「孤竹漫画」文本 —— 闪屏挂了导航也不受影响。

## 10. 验收口径

1. 冷启动（先把 `cache.db` 挪走）+ 真图源：窗口出现即动画；揭幕时 hero 与分类横条**已有封面**。
2. 二次启动：动画期间没有网络等待，揭幕即内容。
3. 落位：字标落进左上角，「Guzhu Comic」不动；过程中不出现两个 GuZhu；落位后无残留动画。
4. 动画期间点一下 / 按 Esc：立刻揭幕。
5. Windows 关掉动画（`prefers-reduced-motion`）：只淡入淡出。
6. `splash.enabled: false`：完全回到现在的行为。
7. **重点看开场那一瞬间有没有白**（§3.4）：glass 开 / 关各看一次。
8. dev 与打包态各看一次；"秒开"只认打包态的数字。

## 11. 风险 / 不做的事

- 窗口**本身**出现的时间（WebView2 启动 + dev 态模块图）闪屏改善不了：它只能保证"窗口一出现就有东西"。
- 字标路径的手感要你看过真机再定稿；不满意就切 `style: font`。
- §3.4 的 `hidden=True` 兜底与"秒开"是交易关系，先真机看，不盲改。
- 不做：音效、二次动画、把动画时长做成"无限等数据"。
