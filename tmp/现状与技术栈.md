# 现状与技术栈 — 孤竹漫画（guzhu_comic）

> **这是主文档**：先讲现状（现在有什么、跑得怎么样、发到哪儿），再讲技术栈（每一层用什么、为什么）。
> 逐轮过程与验收记录在 `tmp/STATUS.md`，专项设计在 `tmp/*设计.md`，文档地图见 `tmp/README.md`。
> 最后更新：2026-10-15 夜（P0 桥 + P1 整页图解扰 + 桌面回归修复 + 安卓签名版 APK + 阅读器破图自愈 + 搜索折叠）。

## 0. 一句话

本地优先的漫画阅读器：**Python 后端直连图源**（jmcomic + curl_cffi 扛 TLS 指纹），前端是**一套不用框架的 Vite/TS 应用**，
壳分别是 pywebview（Windows 桌面）与 AndroidX WebView（安卓）。不登录、不上传，数据全在本机。

## 2. 技术栈

### 2.1 一层的选择与理由

| 层 | 桌面 | 安卓 | 为什么 |
|---|---|---|---|
| UI 壳 | pywebview 6.2.1（WinForms + **WebView2**） | AndroidX WebView（`androidx.webkit` 1.17.1） | 一套前端两处跑；不引入 Flutter/RN 这类"另一套生态" |
| 前端 | 手写 TS + Vite 8.3.4（**不用框架**，页面上自定义元素） | 同一份 `frontend/dist` | 页面逻辑已经写完且能跑；框架化是纯成本 |
| 桥 | **本地 HTTP JSON-RPC**：`POST /api` + `X-Guzhu-Token`，页面地址带 `?t=` | 同一套 | `js_api` 在安卓 WebView 上根本没有；顺带堵上"同机任意进程能读 127.0.0.1:47753"的洞 |
| 页面来源 | 包内本地静态服务（端口 47753，占用则回退到 47760） | 同上（壳把 `assets/web` 解包到 `files/dist`） | 页面与图片**同源**，省掉 CORS 与一堆绝对路径问题 |
| Python 运行时 | 3.14.6（仓库 `.venv`） | **Chaquopy 17.1.0，CPython 3.13.16**（进 app 进程） | 安卓上要跑的就是 `backend/` 那套，Chaquopy 能原样带进去 |
| 图源客户端 | `jmcomic` + `curl_cffi`（impersonate="chrome"） | 同左，`curl_cffi 0.16.3` 的官方 `android_24_arm64_v8a` 轮子 | 图源要 TLS 指纹，`requests` 过不去 |
| 下载 / 缓存 | `ThreadPoolExecutor` + 自写状态机 | 同左 | 现有实现够用；安卓后台保活是**待做**项（`dataSync` 前台服务） |
| 存储 | sqlite（`data/app.db`、`cache/cache.db`）+ 文件缓存 | 同左 | 零依赖、单文件、好备份 |
| 前端热更 | `~/.jmreader/web` 覆盖层，静态服务每请求重挑根 | 同机制可用，但还没在安卓上定策 | 前端改动不必重发安装包 |
| 打包 | PyInstaller 6.22.3（onedir） | Gradle 9.8.1 + AGP 9.4.0 + Chaquopy 17.1.0 | onedir 启动快、好排查；安卓走标准 APK |

### 2.2 版本线（核对过的，别随手改）

- **安卓**：`minSdk 26` / `targetSdk 36` / `compileSdk 37` / 只出 `arm64-v8a`（`curl_cffi` 只有 arm64 轮子）
- **Chaquopy 3.13**：它的轮子仓库（`chaquo.com/pypi-13.1`）里 `cffi` / `pillow` / `pycryptodome` / `pyyaml` 的 arm64 轮子**只到 cp313** → 构建机必须另装 Python 3.13（`gradle.properties` 的 `guzhu.buildPython`）
- **pip 段写死 `--no-deps` + 显式锁版本**：`curl_cffi 0.15+` 声明 `cffi>=2.0.0`，而安卓上没有 cffi 2.x 轮子 → 硬压 `cffi==1.17.1`；连带 `chaquopy-libffi` / `chaquopy-libjpeg` / `chaquopy-freetype` / `pycparser` 必须**显式点名**（不加就构建成功、运行期 dlopen 失败）
- **跑 Gradle 的 JDK**：用 Android Studio 自带的 **JBR 25.0.3**（`D:\Andriod Studio\jbr`）；系统 JDK 26 太新，Gradle 9.8.1 跑不动
- **不挂 Kotlin 插件**：AGP 9 起 Kotlin 内置，再挂 `org.jetbrains.kotlin.android` 会硬失败
- `android/` 里两条变体：`full`（arm64 + 真 `curl_cffi`，回真机）、`ui`（x86_64 + `curl_cffi` 换成"一调就抛"的桩，只跑模拟器）

### 2.4 桥（P0 之后的样子）

- 壳生成一次性 token → 起本地静态服务 → 页面地址给成 `http://127.0.0.1:47753/?t=<token>`；
  前端 `frontend/src/bridge.ts` 看到 `?t=` 就把 `window.pywebview.api` **垫**成 HTTP 版（`POST /api`，头带 token），
  页面上那几十处 `window.pywebview.api.xxx()` 一行都不用改。
- **`?t=` 优先于原生桥**：桌面壳即使不挂 `js_api`，pywebview 也会注进来一个**空的** `window.pywebview.api`
  ——"它在不在"判不出"桥通不通"。而且它启动那几百毫秒会注两遍、每遍**整块重写** `window.pywebview`，
  所以垫片要挂不止一次（监听 `pywebviewready` 重挂）。**这条踩过并已回归用例覆盖**。
- 受保护前缀：`/images`、`/downloads` 与 `/api` 一律要 token（无 token → 403），防止同机其它进程读图。

### 2.5 安卓壳（`android/app/src/main/java/.../MainActivity.kt`）

- 启动链：Activity → 解包 `assets/web` → `files/dist`（每次先 `deleteRecursively()`）→ Chaquopy 起 `android_boot.py`
  → Python 起本地静态服务（47753）→ WebView 加载带 `?t=` 的地址；返回键交给页面路由。
- 让开状态栏 / 导航栏 / 键盘（targetSdk 35 起强制 edge-to-edge）。
- 探针：`--ez guzhu.probe true` 会跑 `guzhu_probe.py`（11 步，逐条打 logcat 与屏幕），**不在正常启动路径上**。

| 出调试包 | `scripts\build_android.ps1 :app:assembleFullDebug` | `app-full-debug.apk`（48.2 MB，调试签名，`run-as` 可用） |

## 3. 关键约束与踩过的坑（都是实测出来的）

1. **整页图是打过乱的**：图源把整页切成 `num` 条横带倒着重排，`num` 同一话每张都可能不同（305124 是 16/4，422866 是 10/14）。
   解扰规则**全项目只写一份**：`backend/descramble.py` 的 `band_plan()`，桌面拿 jmcomic 自带解码逐字节对拍。
2. **Chaquopy 的 Pillow 没编 webp**，而 jmcomic 的 `JmImageResp.transfer_to` 把 `open_image()` 当**函数实参先求值** ——
   于是安卓上**每张图**（连 `num==0`、根本不用解的）都要过 PIL → 全失败。修法：下载时 `decode_image=False` 只落原图，
   再自己解扰（安卓用系统 `BitmapFactory` + `Canvas` + `Bitmap.compress(WEBP, 90)`，走 Chaquopy 的 Java 桥，不碰 NDK）。
3. **别吞异常**：`_download_one` 曾经 `except: return False`，症状是"阅读器一直转圈"，日志里一个字都没有，
   整整查了一天。现在同一章节第一次失败必留一行 log。
4. **桥的判据**：见 §2.4。桌面冻结态曾因此整页无数据，而设备端 / 无头 Chrome / 30 支检查全是绿的。
5. **pywebview 启动会注两遍桥**：第二遍重建在飞回调表 → 那些 promise 永不 settle。启动闸门必须等"最后一次注入安静下来"。
6. **`js/api.js` 是整块重写 `window.pywebview`**，不是往 `api` 上加方法 —— 任何自己挂的垫片都会被打回。
7. **Windows 写文件坑**：`Set-Content` 默认 GBK、`>` 重定向出 UTF-16、`apply_patch` 在 PS 里不可用；
   写脚本一律 UTF-8 无 BOM，`.ps1` / `.py` 各自按原行尾处理。
8. **截图**：设备必须 `cmd /c "...adb.exe exec-out screencap -p > 文件"`，PowerShell 直接重定向会弄坏 PNG。
9. **单实例**：两个实例会抢同一端口与同一份 user data，WebView2 自己也会闹脾气 → 命名互斥体 + 把已有窗口拉到前台。
10. **Host 白名单**：本地服务只认回环 Host，防 DNS rebinding。
11. **资源同步别忘清目标**：`Copy-Item` 只覆盖同名文件，APK 里曾同时躺着 5 份历史前端 bundle。
12. **签名**：release 与 debug 签名不同 → 同机换装先 `adb uninstall`；以后升级必须同一个密钥库。
13. **带 token 的 URL 别再拼一个 `?`**：单张图的重试原来是 `src + '?r=' + n`，而打包态 / 安卓的图片 URL 上
    已经带了 `?t=…` —— 服务端 `parse_qs` 把它解析成 `TOKEN?r=1`，于是**每次重试都 403**，首帧没下来的图
    永远补不回来（安卓上就是「网络一抖几张空着、整本下完也不出图」）。要接着原有 query 拼（`&r=`）；
    回归 `tmp/_check_reader_retry.py`。
14. **触屏上"滑"完浏览器还会补一下 `click`**：一次左滑既命中 `touchend` 里的翻页，又会在原地补一个 `click`
    （那个 handler 按 x 判"点左右两侧翻页"）→ **一次滑动翻两页**。做法：滑动结束时记 `swipedAt`，
    click 侧 500ms 内一律忽略。回归 `tmp/_check_reader_gesture.py`。
15. **品牌字标的笔迹只有一份**（index.html 里那枚闪屏 SVG），而闪屏揭幕会把整层 `remove()` ——
    要用字标的地方必须在**揭幕之前**抄一份进内存（`main.ts` 里 `rememberBrandMark()` 紧跟 `bootSplash()`）。
    抄晚了一步不报错，只会静默退回那张方头像（`components/brand.ts`）。
16. **双击放大的宽度别用 `transform: scale()`**：transform 不改布局，放大后看不见的那部分**拖不出来**。
    做法是把图片宽度那档翻倍、整列铺成 200%，靠页面横向滚动去看。注意 `--reader-col` 是**内联**写在
    `.reader` 上的 —— CSS 类盖不过内联自定义属性，还原得由 JS 把设置里那一档写回去。

## 5. 已知缺口与下一步

- **真机手感**：长图渲染上限、一话 200 张图的内存、后台下载保活、毛玻璃掉帧（T3~T6）—— 模拟器基线 ≠ 真机。
  **用户实测：手上的鸿蒙机（Mate 80 Pro）可装可用**（2026-10-15；Host 侧只有华为 `hdc`，所以只能拷贝安装、不能用 `adb` 调试）—— 见 `tmp/安卓真机连接与调试操作手册.md`。
- **安卓后台下载**：`dataSync` 前台服务还没做（Android 15 起 24 小时内累计 6 小时上限，要靠断点续传）。
- **桌面 exe 没重打**：已发布的 0.1.1 是 P0 之前的壳（走 `js_api`，能用）；要让桌面也吃上 `?t=` 桥，得重出一版（含 `version.py` 的 `APP_VERSION` 与 `build_exe.ps1 -Version` 同步）。
