# 后端能力接入评估（哪些 jmcomic 能力值得做进前端）

> 依据：`tmp/交接文档.md` §6、`README.md` 特性表、以及 2026-10-13 在本机对 jmcomic 2.7.8 的实测。
> 排序口径：**体感收益 ÷ 实现成本**。每条都标了后端改动、前端改动与实测证据。
> 状态：A1 / A2 / A3 / B1 / B2 / B4 / B5 已于 2026-10-13 实施（见 `tmp/STATUS.md`）；剩 A4（只看汉化，**2026-10-14 用户决定暂缓**）与 B3（整本离线）。

## 0. 一句话结论

最划算的三件事：**搜索范围下拉**（作品名 / 作者 / 标签 / 角色）、**排序切换**（最新 / 观看 / 收藏 / 评分）、**详情页把已经拿到却没用的字段铺出来**（发布日期、更新日期、评论数、相关作品）。这三件都不动客户端、不需要登录、也不增加网络请求。

需要更正交接文档一处：§6.3 说 `sub_category='chinese'`（只看汉化）"几乎零成本"，**在当前客户端上不成立**，传了会被静默忽略（见 §3）。

## 1. 现状：前端已经吃到的能力

| 后端接口（`backend/api.py`） | 前端调用点 |
|---|---|
| `search` / `get_ranking` | `pages/search.ts` / `pages/popular.ts` |
| `get_album_detail` | `pages/detail.ts`、`pages/reader.ts` |
| `get_chapter` | `pages/reader.ts` |
| `save_progress` / `get_progress` / `get_album_progress` / `get_history` | `reader.ts` / `detail.ts` / `history.ts` |
| `get_settings` / `save_settings` / `get_cache_stats` / `cleanup_cache` / `clear_cache` | `pages/settings.ts` |

即：搜索、榜单、详情、章节图、进度、缓存设置都已接通；下面评估的是 jmcomic 里**还没接**的部分。

## 2. A 档：建议立刻做（不动客户端、不用登录）

### A1 搜索页「搜索范围」下拉 ★★★★★

- 能力：`search_site` / `search_work` / `search_author` / `search_tag` / `search_actor` —— 五个方法签名完全一样，只是内部的 `main_tag` 取 0 / 1 / 2 / 3 / 4。
- 实测（关键词「中文」，当前 API 客户端）：站内 80 条、作品名 6 条、作者 63 条、标签 80 条、角色 19 条。
- 后端：`API.search(keyword, page=1, scope='site')`，内部查表分发到对应方法；缓存 key 从 `search:<kw>:<page>` 变成 `search:<scope>:<kw>:<page>`。
- 前端：`pages/search.ts` 输入框旁加一个下拉（站内 / 作品名 / 作者 / 标签 / 角色），选中项写进 URL（`#/search?q=..&scope=author`），刷新后还能复现。
- 体感：现在 `search_site` 是大杂烩，搜作者名会混进一堆无关本子；限定作者后命中率立刻不一样。

### A2 搜索 + 榜单「排序」切换 ★★★★

- 能力：`order_by` = `mr` 最新 / `mv` 观看 / `tf` 收藏 / `tr` 评分 / `mp` 图片数 / `md` 评论数。
- 实测：榜单 URL 现在就是 `categories/filter?page=1&order=&c=0&o=mv_w`（`o` = 排序_时间），说明 `order_by` 参数直接生效；搜索同理。
- 后端：`search` / `get_ranking` 各加一个 `order_by` 参数（白名单校验，非法抛 `ValueError`），缓存 key 带上。
- 前端：`pages/popular.ts` 的榜单下拉旁边再加一个排序控件；`search.ts` 顺手同一行。
- 体感：「按收藏排序」找高质量本子比「按观看」准，几乎零学习成本。

### A3 详情页补字段 + 「相关作品」★★★★（2026-10-13 已完成）

- 现状：`get_album_detail()` 只返回 12 个字段，而 `album` 对象里还有一批现成没用上的：`pub_date`、`update_date`、`comment_count`、`related_list`（每项含 id / name / author / description）、`works`、`actors`、`series` / `series_id`。
- 后端：**只加字段，不加请求**（同一个对象里取）。⚠️ `album:<id>` 缓存 24 小时，老缓存没有新字段 → 把 key 升成 `album:v2:<id>`，否则会读到缺字段的旧 JSON。
- 前端：`detail.ts` 的 meta 行补「更新：2026-09-30 · 评论 4434」；章节列表下方铺一排「相关作品」卡片（点击进 `#/album?id=`）。
- 体感：信息量变厚 + 顺藤摸瓜找更多作品，属于"一进详情页就感觉不一样"的改动。

### A4 「只看汉化」 —— 先看 §3，成本比文档说的高一档（**2026-10-14 用户定：不做**）

## 3. 勘误：「只看汉化」在当前客户端上是空操作

- 交接文档 §6.3 推荐用 `sub_category='chinese'` 做「只看汉化」，并称"几乎零成本"。
- 实测结论：**不成立**。项目现在建的是 `JmOption.default().new_jm_client()` → `client_key == 'api'`（`JmApiClient`）：
  - `JmApiClient.search` 的源码注释写着"移动端暂不支持 category和sub_category"；
  - `JmApiClient.categories_filter` 同样只取 `page/time/category/order_by`，`sub_category` 被丢掉（实测传了 `chinese`，生成的 URL 里压根没有 sub 段）。
- 也就是说：界面加了「只看汉化」，用户点了却什么都不变 —— 正是交接文档 §2.2 描述的"点了保存却不生效"那类坑。
- 真要做，得引入 **HTML 客户端**：`JmOption.default().new_jm_client(impl='html')`，它支持
  - `/albums/doujin/sub/chinese?page=1&o=mv&t=w`（实测同人 + 汉化 周榜 42 条）；
  - `/search/photos/.../sub/chinese`（实测 `search_tag('中文')` 80 条、`search_work('中文')` 5 条）。
- 建议做法（A4）：**双客户端**
  - 详情 / 章节图 / 下载 / 进度继续走现有 API 客户端（快、稳、缓存链路已跑通）；
  - 只有"汉化筛选后的搜索 / 榜单"走 HTML 客户端；
  - 两者共用同一份 `JmOption`（代理、重试配置都继承），但 HTML 域名体系与 API 不同（实测 html → `comic18j-guta.site`，api → `www.cdnhjk.net`）；
  - 缓存 key 加标记（如 `search:html:chinese:...`），别和 API 结果串味。
- 成本：后端约 40 行（懒建 html client + 两个方法分支）；前端只是两个筛选控件。收益：汉化筛选，属于"一半用户默认就想要"的功能。

## 4. B 档：值得做，但要先写点后端

### B1 详情页「评论预览」★★★★（2026-10-13 已完成，做成详情页右侧评论区）

- 能力：`album_pagination(album_id, page=1)` → **只读，不需要登录**。
- 实测：某热门本子第 1 页 10 条、总数 4434；每条有 `nickname`、`content`、`is_spoiler`、`created_at`（`likes` 网页端不提供，恒为 `None`）。
- 后端：新增 `get_comments(album_id, page=1)`，TTL 取短一点（建议 600s，评论更新快），返回前剥掉 raw_data 里的冗余字段。
- 前端：`detail.ts` 加「热门评论 · 4434」区块，默认显示 3 条 + 「看更多」；带 `is_spoiler` 的默认折叠，点一下才展开。
- 注意：`album_comment()`（发评论）要登录，**别碰**。

### B2 榜单 / 搜索条件持久化 ★★★★（零后端，2026-10-13 已完成）

- 现在刷新页面会回到"周榜 + 全部"（交接文档 §7 第 5 条）。
- 纯前端：localStorage 记 `{range, category, order_by, scope}`；阅读器浮层里的模式 / 背景 / 宽度同理。
- 落地：新增 `frontend/src/store.ts`（localStorage 读写 + 白名单校验，存储被禁用就静默回默认值）；
  热门页记 `{range, category, sort}`，搜索页记 `{scope, sort}`，搜索页的 URL 参数优先级更高。
- 体感：单个改动很小，但天天用得到。

### B4 本地收藏 + 「我的收藏」页 ★★★★（不登录）—— **2026-10-13 已完成**

- 决定：**账号体系全部不做**（`login` / `favorite_folder` / `toggle_favorite_album` / `daily_checkin` 都要落盘凭据，有隐私风险）；收藏改成**本地版**，和 jmcomic 账号无关。
- 后端：`data/app.db` 加表 `favorite(album_id PRIMARY KEY, title, cover_url, added_at)`，加四个 js_api：`add_favorite(album_id, title, cover_url)` / `remove_favorite(album_id)` / `is_favorite(album_id)` / `get_favorites(limit, offset)`。
- 前端：详情页顶部一颗心（点完立刻变、失败回滚）；新增 `#/favorites` 路由 + 左侧导航一项，列表复用 `renderAlbumList`。
- 好处：和"最近阅读"一样属于用户数据（在 `data/` 里，清缓存不动它）；代价：只在本机，和网页端账号收藏不同步。
- 注意：别把"是否收藏"塞进 `album:<id>` 详情缓存，那个缓存有 24h TTL，收藏态要单独查本地表。
- **实际落地**（2026-10-13）：表建在 `data/app.db`（和 `history` 同库，清缓存不动）；接口做成 `is_favorite` / `toggle_favorite` / `remove_favorite` / `get_favorites` 四个（`add` 不做 —— 心形只有"切换"一种语义，前端用不上单独加接口）；详情页顶部加心形（乐观更新 + 失败回滚），新增 `#/favorites` 页 + 左侧导航「收藏」，卡片角上一个垃圾桶取消收藏。没有新配置项。

### B5 「论坛」页（全站评论流）★★★★（**2026-10-13 已完成**：侧栏导航「论坛」+ `#/forum`）

> 2026-10-14 补：用户报"论坛是空的"，查下来是**首屏那一下**的观感问题（等图源时页面什么都不铺 + 图源冷启动慢），不是接口没数据——真图源第 1 页稳定 10 条。已修：等的时候铺评论骨架、首屏失败自动重试 2 次、桥迟到自己接上；整个修复见 `tmp/STATUS.md`「首屏修复」。

- 能力：**两个客户端都自带** `forum_pagination(page)` —— HTML 客户端打 `/ajax/forum_more`，API 客户端打 `/forum?mode=all&page=N`（就是 JM 站上的"全站评论区 / 广场"）。**只读，不需要登录**。
- 实测（2026-10-13，JmApiClient）：`forum_pagination(page=1)` → `total=5000`（服务端封顶）、`page_count=500`、每页 10 条；第 2 页数据与第 1 页不同。
- 每条评论拿到：`comment_id` / `album_id`（AID，可能是 `0` = 没挂本子）/ `user_id` / `nickname` / `content`（**API 客户端已把 HTML 洗干净**，实测是纯文本）/ `created_at`（`Oct 13, 2026` 这种格式）/ `spoiler` / `likes` / `replies`（嵌套回评）。`raw_data` 里另有 `name`（形如 `JM181144`）与用户头像文件名 `photo`。
- 链接本子的成本：**封面地址是拼出来的，零请求**（`JmcomicText.get_album_cover_url(aid)` → `https://cdn-msp.../media/albums/<aid>.jpg`，和详情页同一套）；**标题要额外请求**（`get_album_detail`，有缓存）。所以卡片可以两档做：① 只给封面 + `JM<aid>`，点开进详情（零额外请求）；② 并发拉这几部的详情补上标题（每页 10 次、并发 5，读完进缓存，等于顺手预热了详情页）。
- 后端（**已落地**）：`get_forum(page=1)` → `{total, has_more, items:[{comment_id, nickname, content, created_at, spoiler, reply, reply_count, album_id, cover_url}]}`；缓存 key `forum:<page>`，时长复用 `cache.comment_ttl`。`likes` 实测 50 条全 0（移动端接口不给），没进契约。
- 前端（**已落地**）：等图源时先铺 5 条评论骨架（`renderCommentSkeleton`）、首屏失败自动重试 2 次；新增 `pages/forum.ts`、侧栏导航「论坛」、`pywebview.d.ts` 契约；排版复用详情页评论区那套（剧透遮住、内容一律 `textContent`）。标题另走一个 `get_album_titles`（并发 5、复用详情缓存）。
- 体感：多了一个能瞎逛的入口，点一条就能顺着进对应本子；本质上是**内容发现**而不是阅读本身。
- **不做**：发帖 / 回帖（要登录，已定不做）；点赞（要登录）。
- 风险：这是公开评论区，**广告和垃圾信息是常态**（实测第 1 页就有两条带"梯子/引流"字样的），所以别做进首屏、别做默认落地页，放导航里当"随便看看"。

### B3 整本离线下载 ★★（大工程）

- `JmOption.download_album` / `download_photo` 自带并发、断点与命名规则，但和我们自己的 `.part` 临时名、整话保留策略、"正在看的不删"是两套逻辑（交接文档 §6.3 已提示代价）。
- 建议单独立项：先做"整本加入下载队列 + 进度 UI"，下载仍复用现有下载器（保住缓存策略），另加一张 `download_queue` 表。

## 5. C 档：先别做（含一处文档勘误）

| 候选 | 判断 |
|---|---|
| 账号体系（`login` / `favorite_folder` / `toggle_favorite_album` / `daily_checkin`） | **已定：不做** —— 要落盘账号凭据，有隐私风险。收藏改为本地版，见 §4 的 B4。 |
| 换线路（`get_domain_list` / `set_domain_list`） | 只有域名全挂时才用得上，平时是死功能。建议做成"图源异常时自动换域名 + 设置页只读展示"，而不是给用户一个手动按钮。 |
| 用 `get_meta_data()` 显示"图源版本" | **交接文档 §6.3 判断有误**：实测返回 `{impersonate, headers, proxies, cookies}`，是 HTTP 客户端元数据，没有版本号。想显示图源版本应该用 `JmModuleConfig.APP_VERSION`（启动日志里 `api.setting: change APP_VERSION from [2.1.7] to [2.1.11]` 就是它）。 |
| 论坛 / 广场（`forum_pagination`） | **2026-10-13 改判**：从"先别做"挪到 §4 的 B5 —— 客户端自带、只读、不用登录，实现成本不高，用户 2026-10-13 主动问起。 |
| 发评论 / 发帖 / 点赞 | **不做**：都要登录。 |
| `decode` 等解密链路 | 与阅读器无关（交接文档 §6.5），现有 `get_chapter` 已经覆盖。 |

## 6. 推荐实施顺序

1. A1 搜索范围 + A2 排序 —— 同一批后端改动（`search()` / `get_ranking()` 各加参数），前端两个控件（**2026-10-13 已完成**）
2. B2 条件持久化 —— 纯前端，顺手做（**2026-10-13 已完成**）
3. A3 详情页补字段 + 相关作品（**2026-10-13 已完成**，缓存键已升成 `album:v2:`）
4. B4 本地收藏 + 「我的收藏」页（不登录）（**2026-10-13 已完成**）
5. B1 评论预览（**2026-10-13 已完成**：详情页右侧栏，条数由 `detail.comment_preview` 控制，`cache.comment_ttl` 控制缓存；顺带做了章节折叠 `detail.chapters_collapse`）
6. A4 只看汉化（引入 HTML 客户端）
7. B3 整本离线下载（单独立项）

## 7. 实施纪律与踩坑清单

- 本次评估里的候选**都不需要新配置项**；若后续要加，记得按交接文档 §2.2 一次改 5 处。
- 后端改接口 → 同步 `frontend/src/pywebview.d.ts`（类型契约唯一出处）。
- 缓存 key 变更（A1 的 scope、A2 的 order_by、A3 的字段版本）等于旧缓存自然失效，属预期行为，不用写迁移。
- 改完前端必跑 `cd frontend && .\node_modules\.bin\tsc.cmd --noEmit -p tsconfig.json`（`noUnusedLocals` 开着）。
- 接口来的文本一律走 `textContent` / `escapeHtml`（作者名、评论里真有 `&`、`<`）。
- 提交前用真窗口过一遍：首页 → 搜索 → 详情 → 阅读 → 返回 → 最近阅读 → 设置。
