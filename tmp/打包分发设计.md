# 打包分发设计 — 孤竹漫画（Windows .exe 优先）

> 写于 2026-10-14。环境：Python 3.14.6 / pywebview 6.2.1 / PyInstaller 6.22.3 / Node 24.18 / Vite 8.3。
> 文中标「实测」的都是这次真跑过的（命令与原始输出见 §12）；标「未验证」的别当结论用。
> 验证用的入口是 `tmp/_probe_exe.py`（真 `frontend/dist` + 真 `API()` + 真窗口），**不是** `main.py` ——
> §4 的 P0 迁移还没落到 `main.py` 上，所以现在 `scripts/build_exe.ps1` 打出来的包会去连 5173（那台没开就是白屏），这是预期的。

## 0. 一句话结论

| 问题 | 结论 |
|---|---|
| 打成什么 | **PyInstaller `--onedir`**（**不要 `--onefile`**）：一个目录 = 1 个 exe + `_internal/`，zip 分发，解压双击就能用 |
| 前端怎么进包 | `frontend/dist` 当静态资源打进 `_internal/dist`，进程内起一个**本地 HTTP 服务**挂它。**不走 `file://`**（理由见 §4-P0-6） |
| 端口 | 固定 **47753**（实测空闲），占用时 47754…47760 依次退让；依据见 §5 |
| 用户机器需要什么 | 只要 **WebView2 Runtime**（Win11 自带；Win10 1803+ 多数自带）+ **.NET Framework 4.6.2+**（Win10 1803+ 自带）。**不需要 Node / Python / Vite / .NET 6+** |
| 体积 | **onedir 38.9 MB / zip 19.9 MB**（实测，含裁剪） |
| 杀软 | onedir + 不开 UPX + 带版本信息；本机 Defender（引擎 1.1.26090.9）全量扫描 **no threats**（实测） |

三条优先级的落点：**优先级 1 → §3 + §4 + §7**；**优先级 2 → §6 + §8**；**优先级 3 → §9**。

## 1. 现状：为什么"`npm run build` 完了也打不出能用的包"

## 4. 迁移清单

### P0 —— 不改就跑不起来

#### P0-1 `backend/config.py`：配置落到用户目录

现在：`CONFIG_PATH = Path(__file__).resolve().parent.parent / "config.yaml"` → 冻结后是 `<exe>/_internal/config.yaml`。装在 `Program Files` 就是**只读**（设置页保存直接炸），装在别处则**每次升级包都被覆盖**。

改法（建议抽一个 `backend/paths.py`，`api.py` 的 `APP_DIR` 也搬过来，避免循环导入）：

```python
# backend/paths.py（新增）
import sys
from pathlib import Path

APP_DIR = Path.home() / ".jmreader"          # 今天 api.py:80 就在这儿，统一到一处

def is_frozen() -> bool:
    return bool(getattr(sys, "frozen", False))

def bundle_dir() -> Path:
    """只读资源根：冻结态 = _MEIPASS（即 <exe>/_internal），源码态 = 仓库根"""
    if is_frozen():
        return Path(getattr(sys, "_MEIPASS", Path(sys.executable).parent))
    return Path(__file__).resolve().parent.parent

def config_path() -> Path:
    # 开发态继续吃仓库根的 config.yaml（保持现在的手感），冻结态落用户目录
    return (APP_DIR / "config.yaml") if is_frozen() else (bundle_dir() / "config.yaml")

def dist_dir() -> Path:
    return bundle_dir() / "dist" if is_frozen() else bundle_dir() / "frontend" / "dist"
```

- 冻结态首次运行：`config.yaml` 不存在就用 `DEFAULT_CONFIG` 写一份（`save_config(load_config())` 一句话），这样用户能直接看到文件、也能直接改。
- 更彻底的做法是**开发态也搬到用户目录**（仓库里那份 `config.yaml` 退化成模板）。好处是只有一条路径；代价是现在这台开发机要手工拷一次。**建议先按上面的双路径走，等跨平台时再统一**。

#### P0-2 `main.py` + 新增 `backend/server.py`：本地静态服务

```python
# backend/server.py（新增，复用 api.py 里 _QuietHandler 那套 extra_roots 前缀表）
def start_static_server(dist: Path, extra_roots: dict[str, Path], port: int = 47753) -> str:
    """返回 base url；端口被占就 +1 依次试，最后退回 0（系统随机）"""
    for candidate in list(range(port, port + 8)) + [0]:
        try:
            srv = ThreadingHTTPServer(("127.0.0.1", candidate), partial(_Handler, directory=str(dist)))
        except OSError:
            continue
        srv.extra_roots = extra_roots          # {"/images": CACHE_DIR/"images", "/downloads": download_dir}
        threading.Thread(target=srv.serve_forever, daemon=True).start()
        return f"http://127.0.0.1:{srv.server_address[1]}"
```

```python
# main.py
if dev_cfg.get("use_dev_server"):
    url = dev_cfg["url"]      # 开发态：vite dev server
else:
    base = start_static_server(dist_dir(), {"/images": ..., "/downloads": ...})
    url = base + "/"
api = API(base_url=base if not dev_mode else None)
```

配套：`API` 现在自己 `_start_img_server()`（`backend/api.py:169`）。改成**服务先起、base 注进来**：

```python
class API:
    def __init__(self, base_url: str | None = None):
        ...
        self.img_base = base_url or self._start_img_server()   # 源码态/无服务时保持原行为
```

两个选择：

- **方案 A（推荐）**：一个服务、一个端口（根 = dist，`/images`、`/downloads` 走前缀表）。好处：图片与页面**同源**（省掉跨源）、WebView2 的图片 HTTP 缓存跨次有效、只监听一个端口。
- 方案 B（改动最小）：dist 一个固定端口 + 图片服务维持 `port 0` 随机。代价：多一个监听端口；图片 URL 每次开窗都变 → WebView2 那层图片缓存跨次失效（磁盘缓存不受影响，所以只损失一点点）。

#### P0-3 `webview.start`：持久化 WebView2 存储

```python
webview.start(debug=dev_cfg["debug"], func=..., private_mode=False,
              storage_path=str(APP_DIR / "webview"))
```

实测：加了这个之后 `localStorage` 可写、且能跨次留存（`private_mode=False` 时 `clear_user_data()` 会直接 return，见 `edgechromium.py:122`；user data 落在 `~/.jmreader/webview`，不再进临时目录）。

#### P0-4 `config.yaml`：新增/调整三个键（**要动 5 个地方**，见 `tmp/交接文档.md` §2.2）

```yaml
dev:
  url: http://localhost:5173
  use_dev_server: false    # 新增：发布包 false → 走本地静态服务
  debug: false             # 发布默认关（现在是 true）
server:
  port: 47753              # 新增：前端静态服务端口
```

五处：`backend/config.py` 的 `DEFAULT_CONFIG`、`config.yaml`、`frontend/src/settings.ts`（接口 + 默认值）、`frontend/src/pages/settings.ts` 的 `GROUPS`、**`backend/api.py` 的 `save_settings()` 白名单**（漏了就是"点了保存没反应"）。

#### P0-5 `dev.debug` 在发布包必须 `false`

`debug=true` 会开 DevTools 并让 pywebview 输出日志。发布包用 `DEFAULT_CONFIG` 的值（上面已改 `false`），别让用户机器上的旧 `config.yaml` 影响新装。

#### P0-6 Vite 侧：**不用改**

- **不需要 `base: './'`**：我们是从一个 HTTP 根路径服务的，`dist/index.html` 里的 `/assets/index-*.js` 绝对路径正常工作（实测加载成功）。只有在 `file://` 或子路径部署时才需要改。
- `npm run build`（= `tsc && vite build`）命令不变，产物 `frontend/dist` 实测 0.19 MB。
- **`file://` 方案为什么否**：① `dist/index.html` 是 `<script type="module" crossorigin>`，ES module 要走 CORS 检查，`file://` 的 origin 是 opaque → 直接被拦；pywebview 有 `ALLOW_FILE_URLS` 开关（给 WebView2 加 `--allow-file-access-from-files`）能绕过，但那是主动削弱安全策略；② `localStorage` 在 `file://` 下不是稳定 origin，"主题/偏好跨次留存"这个诉求满足不了；③ 起本地 HTTP 服务的成本约 10 行代码，还顺带解决图片同源。**所以：HTTP，不 file://。**
- 顺带：`frontend/index.html` 的 `<title>frontend</title>` 建议改成 `Guzhu Comic`（窗口标题由 pywebview 的 `title` 决定，但浏览器/任务栏悬停会看到这个）。

### P1 —— 该做（体验 / 分发质量）

1. **`.ico`**：现在只有 180×180 的 `apple-touch-icon.png`，没有 `.ico`（`frontend/public/` 里只有两张 png）。构建脚本已经用 Pillow 生成多尺寸 `app.ico`（16/24/32/48/64/128/180/256）。180→256 是放大，任务栏大图标会略糊 —— **建议补一张 256×256 的源图**。
2. **单实例**：端口固定后，第二个实例会绑不上。建议：绑定失败且 `GET http://127.0.0.1:47753/` 有响应 → 判定"已在运行"，提示一句后退出（或 `FindWindowW` 把已有窗口带到前台）。
3. **WebView2 缺失检测**：启动前查 `HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}` 的 `pv`（本机实测 `155.0.4283.45`）；缺失时给一句人话 + Evergreen 下载链接，别让用户对着一个白窗口。

## 5. 端口：为什么是 47753

**选型依据**（三条都实测过）：

1. **> 4096**：普通用户进程就能绑，不需要管理员。
2. **< 49152**：Windows 的**动态端口段**是 `49152 + 16384`（本机实测：`netsh int ipv4 show dynamicport tcp` → Start 49152 / 16384）。这个段是给出站连接随机分配的 —— 如果服务绑在 49152 以上，本进程（curl_cffi 那一堆请求）的出站连接可能先随机占到它，导致某次启动"端口被占"。
3. **不在保留段**：本机 `netsh interface ipv4 show excludedportrange protocol=tcp` 只有 `5357`（WSDAPI），47753 不在里面。

**实测**：10 个候选全部空闲（47753 / 47823 / 47123 / 41999 / 45711 / 47251 / 49151 / 49321 / 51080）；最终选 **47753**。

**回退策略**：47753 → 47754 … 47760 依次试；全被占就退回 `0`（系统随机）。

⚠️ 回退的副作用要说清楚：**origin 一变，WebView2 的 `localStorage` 就是另一个 origin**，用户会觉得"主题/偏好被重置了"。所以：首选固定端口，回退时**建议在日志里记一笔**（将来如果不想要这个副作用，就得把主题/偏好搬到后端 `config.yaml`，但那会让首帧主题闪一下 —— 现在 `index.html` 里那段内联脚本靠的就是 localStorage，别改）。

**图片服务**：按 §4-P0-2 合并进同一个端口后，`img_base` 就等于页面 origin，跨源问题一起消失。

## 6. 怎么构建

脚本：`scripts/build_exe.ps1`（**实测可跑通**，产物 39 MB / zip 19.9 MB / 约 25 秒）。

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-build.txt   # pyinstaller>=6.22（实测 6.22.3）
powershell -ExecutionPolicy Bypass -File scripts\build_exe.ps1
```

脚本做的事：`npm run build`（可 `-SkipFrontend` 跳）→ Pillow 生成 `app.ico` → 写 version-file → PyInstaller → 体积报告 → zip。

PyInstaller 参数逐条为什么：

| 参数 | 为什么 |
|---|---|
| `--onedir`（**不是 `--onefile`**） | onefile 每次启动解压自身到 `%TEMP%`，是杀软行为引擎的头号嫌疑；onedir 启动也更快 |
| `--noupx` | UPX 壳会让启发式引擎加权重；省下那点体积不值得 |
| `--windowed` | 发布态不留控制台；**实测 windowed 与 console 行为一致**（页面照样起来、桥照样通） |
| `--icon` / `--version-file` | exe 图标 + 文件属性；"没有版本信息的 PyInstaller exe" 是误报的常见画像 |
| `--add-data "frontend/dist;dist"` | 前端产物 → `<exe>/_internal/dist`（Windows 下分隔符必须是 `;`） |
| `--collect-all webview pythonnet clr_loader curl_cffi jmcomic` | 这几个包的运行时依赖收不全：webview 的 WebView2 DLL / js、pythonnet 的 `Python.Runtime.dll`、clr_loader 的 `ClrLoader.dll`、curl_cffi 的 `libcurl-impersonate`、jmcomic 的动态插件扫描 |
| `--hidden-import clr` | pywebview 的 Windows 后端 `import clr` 是间接的，静态分析常常扫不到 |
| `--exclude-module tkinter / PIL.AvifImagePlugin / test / unittest / pydoc` | 实测砍 15.5 MB（54.4 → 38.9），且功能无回归 |

**两个坑**：

- **`.ps1` 必须存成 UTF-8 带 BOM。** PowerShell 5.1 把无 BOM 的脚本按 ANSI（本机 GBK）读，中文注释会直接把语法解析搞坏（实测：无 BOM → 6 处语法错误；加 BOM → 通过）。这条与 `AGENTS.md` 里"脚本用 UTF-8 无 BOM"的口径冲突 —— 那条是针对 sh/`.py` 的，**`.ps1` 例外**。
- **PowerShell 的 `&` 不会等 GUI（windowed）子系统的 exe**：`& .\GuzhuComic.exe` 立刻返回，看着像"没跑起来"。要等就用 `Start-Process -Wait`，或者轮询进程/产物文件。

## 7. 优先级 1：拿到文件和可执行程序就能用

**交付形态**：`GuzhuComic-0.1.0-win64.zip`（19.9 MB）→ 解压 → 双击 `GuzhuComic.exe`。无安装、无管理员权限、不写注册表、不写 `Program Files`。

## 8. 优先级 2：把杀软误报压到最低

误报**不能归零**（未签名的新 exe + 联网抓图 + 多线程下载 + 写用户目录，本身就是行为引擎的兴趣点），只能压低 + 提供申诉通道。

**已经做到的**（都在构建脚本里）：

- `--onedir`：不做自解压，不往 `%TEMP%` 丢东西。
- `--noupx`：不加壳、不压缩。
- exe 带**图标 + 完整版本信息**（CompanyName / FileDescription / ProductName / FileVersion）。
- 用**官方 CPython**（本机是 python.org 的 `pythoncore-3.14-64`），不用 python-build-standalone / conda 那类被某些引擎特殊照顾的解释器。
- **不写系统目录、不写注册表、不改 hosts、不注入别的进程** —— 全部数据在 `~/.jmreader`，卸载 = 删目录。
- 分发成 **zip**（而不是把裸 exe 传到网盘/网站让人直接下载执行）。
- **实测**：Defender（引擎 1.1.26090.9 / 特征库 1.461.18.0）对整个 onedir 与 exe 全量扫描 → `found no threats`。

**建议补上的**：

1. **代码签名**（唯一能根治 SmartScreen "未知发布者" 和多数启发式扣分的办法）。OV 证书能消 SmartScreen，EV 立刻消。要花钱，**建议先决定买不买**；不买就把"首次运行提示"写进 README。
2. **VirusTotal 过一遍**（70+ 引擎）：国内用户大量装 360 / 火绒 / 腾讯电脑管家，Defender 通过不代表它们通过。发现误报就走各家申诉入口（Microsoft：`https://www.microsoft.com/en-us/wdsi/filesubmission`；360 / 火绒也有各自的白名单申请）。
3. **发布纪律**：同一个构建机、同一个 Python 小版本、同一套 flags，别每次换环境重打 —— 哈希一变就可能重新触发未知文件判定。
4. **别做的事**：不要试图混淆 / 加壳 / 加密"防误报"（反而更像恶意软件）；不要打包 `--key`；不要往包里塞自动更新器。

## 9. 优先级 3：跨平台基础

先看现状：**全仓库的平台判断只有 `backend/glass.py:37` 一处**（`sys.platform != 'win32'` 直接 return），`main.py` / `backend/api.py` 里没有 win32 硬编码，数据目录用的是 `Path.home()`。所以基础是干净的，**现在不需要为跨平台做任何重构**，只要别破坏下面三条边界。

| 平台 | 前端 dist | 后端 | 打包 | 障碍 |
|---|---|---|---|---|
| **Windows x64** | 通用 | 通用 | PyInstaller onedir | 本次已打通 |
| **macOS** | 通用 | pywebview 走 `cocoa`（WebKit）；`glass.py` 自动跳过 | PyInstaller **必须在 mac 上构建**（不能交叉编译） | 需要签名 + 公证（否则 Gatekeeper 拦）；想要毛玻璃得改用 pywebview 的 `vibrancy=True`（mac 专属参数），`backend/glass.py` 那条 DWM 路线在 mac 上是空操作 |
| **Linux** | 通用 | pywebview 走 GTK/QT，要系统库（`python3-gi` 等） | 建议 AppImage / Flatpak | 发行版差异大；`curl_cffi` 有 linux wheel |
| **Android** | 通用 | **pywebview 6.2.1 自带 `webview/platforms/android`**（包内还有 `pywebview-android.jar`），但它是建在 **Kivy + python-for-android + pyjnius** 上的（`from android.activity import …` / `from jnius import autoclass`） | 必须在 Linux（WSL/Docker）上构建 | ① `pythonnet` 是 **Windows/.NET 专属**，Android 上 `backend/glass.py` 不能只是个 `if`，得整个绕开；② `curl_cffi` **没有 android wheel**，网络层要么换 `requests/ssl`，要么自带 CA；③ js_api 桥在 Android 上是 Java 对象注入（`addJavascriptInterface(external)`），时序与桌面不同，要单独验证；④ 没有"打一个 apk"的现成路径，工作量大 |

**现在就守住的三条边界**（未来要不要做 mac/安卓，都不该破坏）：

1. **平台分支只许出现在 `backend/platform/` 门面里**（glass / 单实例 / 数据目录 / 窗口装饰都从这走），业务代码不许出现 `sys.platform`。
2. **数据与配置路径只有一个入口**（§4-P0-1 的 `backend/paths.py`）—— 今天 `~/.jmreader`，Android 上是 app 私有目录，换起来只改一处。
3. **网络层收口**（jmcomic client 的构造、curl_cffi 的 impersonate 参数集中在一处），将来 Android 换实现不用动业务。

**明确不建议现在做的**：为了"将来能上安卓"去引入 Kivy / p4a / Chaquopy。理由：Android 三件套（webview 后端 / 网络层 / 桥时序）都要重写，而且现在没有需求；等真要做时，**core（纯 Python 业务）+ 平台壳** 的重构会比现在猜着做省事得多。
