## 0. 一句话架构

前端 Vite + TypeScript（**没有框架**，手写 hash 路由 + 原生 DOM）跑在 WebView2 里；后端 `main.py` 用 pywebview 开窗，把 `backend/api.py` 里 `API` 类的实例挂成 `js_api`。前端只通过 `window.pywebview.api.xxx()` 调后端，**没有 HTTP 中间层**（唯一的 HTTP 是本地章节图静态服务）。

```text
main.py  ──►  pywebview.create_window(url=http://localhost:5173, js_api=API())
   │                              ▲
   │ 前端 vite dev server (5173)  │  window.pywebview.api.*（pywebview 注入的桥）
   ▼                              │
frontend/src ── hash 路由：#/popular  #/category?c=  #/search  #/forum  #/album?id=  #/read?photo_id=&album_id=  #/history  #/favorites  #/downloads  #/about  #/settings
   │
   └─ 章节图：get_chapter() 返回 http://127.0.0.1:<端口>/images/<photo_id>/<文件名>
      后端起了个 ThreadingHTTPServer 静态服务：一个端口同时喂前端 dist 与图片
```

> 补（2026-10-14 打包后）：上面这张图是**源码态的旧样子**。打包态 `main.py` 不再连 5173 ——
> 它起 `backend/server.py` 的本地静态服务（端口 `server.port`，默认 47753，被占就 47754…47760，最后退 0），
> `/` 挂 `frontend/dist`，`/images` → `~/.jmreader/cache/images`、`/downloads` → 配置里的下载目录（`extra_roots` 那条映射）；
> 只有源码态 + `dev.use_dev_server=true` 才走 5173。数据与配置全在 `~/.jmreader`（`backend/paths.py` 是唯一入口）。

## 2. 后端契约

### 2.1 js_api 全表（`backend/api.py`）

前端能看到的接口就是这些；改动要同步 `frontend/src/pywebview.d.ts`（类型契约的唯一出处）。

| 方法 | 参数 | 返回 | 缓存 | 前端调用点 |
|---|---|---|---|---|
| `search` | `keyword, page=1, scope='site', order_by='latest'` | `[{id,title,cover_url,favorited}]`（收藏态现拼） | `search:scope:排序:kw:page`，`cache.search_ttl`（默认 1h） | `pages/search.ts` |
| `get_ranking` | `time_range, category='all', page=1, order_by='views'` | 同上（`favorited` 现拼） | `ranking:range:cat:排序:page`，`cache.ranking_ttl` | `pages/popular.ts` |
| `get_album_detail` | `album_id` | `{id,title,author,authors,description,tags,likes,views,comment_count,pub_date,update_date,page_count,cover_url,related:[{id,title,author,cover_url}],chapters:[{photo_id,index,title}]}` | `album:v2:id`，`cache.album_ttl`（24h）；缓存里不放封面地址，返回前现拼 | `detail.ts`、`reader.ts`（要标题/封面/章节表） |
| `get_chapter` | `photo_id` | `{photo_id, images:[url...]}` | `photo:id`（只缓存**文件名列表**） | `reader.ts` |
| `get_comments` | `album_id, page=1` | `{total, has_more, items:[{nickname,content,created_at,spoiler,reply}]}` | `comments:id:page`，`cache.comment_ttl`（默认 600s） | `detail.ts`（右侧评论区） |

### 2.3 数据放哪（缓存 vs 用户数据 —— 红线）

根目录：`C:\Users\guzhu\.jmreader\`（`backend/api.py` 里 `APP_DIR = Path.home() / ".jmreader"`）

| 路径 | 内容 | 能不能删 |
|---|---|---|
| `data/app.db` | `history` 表：阅读进度，主键 `(album_id, photo_id)`；`favorite` 表：本地收藏，主键 `album_id`（+ title / cover_url / added_at + `tags_json` / `authors_json` 快照）；`search_log` 表：搜索记录，主键 `keyword`（+ scope / hits / at）；`download_album` 表：整本下载任务，主键 `album_id`（+ total / done / state / error）；`download_chapter` 表：每话状态，主键 `(album_id, photo_id)` | **不能删，删了再生不出来** |
| `cache/cache.db` | `meta_cache` 表：搜索/榜单/详情/章节图列表的 JSON 缓存 | 能删 |
| `cache/images/<photo_id>/<文件名>` | 解密落盘后的章节图 | 能删（就是要清它） |
| `downloads/<album_id>/<photo_id>/<文件名>` | 整本下载的离线副本（目录 = `config.yaml` 的 `download.dir`，默认 `~/.jmreader/downloads`） | **不能删**（删了要重下） |

- `clear_cache()` 只碰 cache，不碰 data；离线副本在 `download.dir`（默认在 `APP_DIR/downloads`）里，两边都动不到它。`cache.max_size_mb`（默认 2048）只约束 `cache/` 整目录。
- 界面记忆（榜单 / 分类、搜索范围与排序）在 WebView2 的 localStorage 里，前缀 `guzhu:`（`frontend/src/store.ts`），键是 `popular` / `search`：既不在 `data/` 也不在 `cache/`，清缓存和定时清理都不碰它。
- **搜索记录不在 localStorage 了**（2026-10-14 搬走）：推荐要用"搜过几次、什么时候搜的"，只有后端算得了，所以进了 `data/app.db` 的 `search_log`；老键 `guzhu:search:recent` 进搜索页时顺手删掉（`pages/search.ts`）。表最多留 200 条、按时间倒序取 12 条当 chips。
- 老版本把 `meta_cache` 和 history 混在一个 `app.db` 里，`_move_legacy_cache()` 负责迁移；老版本下过的封面在 `cache/covers`，启动时直接删（现在封面走远程 URL）。
- 清理策略（`cleanup_cache`）：超上限就从**最久没看过**的章节开始**整话**删，压到上限的 90%；正在下载的（`_dl_photo_ids`）、正在看的（`_last_photo_id`）、最近读过的 3 话留到最后删。后台 `_cache_loop` 每 `cache.cleanup_interval`（默认 600s）跑一次。

### 2.4 章节图的下载链路（`get_chapter` → `_download_*`）

1. `get_chapter(photo_id)`：先查 `photo:<id>` 缓存拿文件名列表；没有就 `client.get_photo_detail(photo_id)` 再缓存。
2. 缺图就 `_spawn_download` 起后台批次（靠 `_dl_batch_lock` + `_dl_photo_ids` 保证**同一话只跑一批**，两批会抢同一个临时文件）。
3. `_download_one`：先写 `.part<原后缀>`（**临时名必须保留真实后缀**，jmcomic 按输出后缀决定编码方式，拿 `.part` 当后缀直接抛错），成功后 rename 成正式名。
4. 返回给前端的 URL 用 `self.img_base` 现场拼 —— **别把 URL 存进缓存**，本地图片服务端口每次启动都变（`port 0` 随机分配）。
5. **预加载走的是同一条路**：`prefetch_chapter` 调 `_spawn_download(photo_id, None, limit=前几张)`，`limit` 让这一批只下开头几张；批次在跑时若又有人要**整话**（用户真进阅读器了），`_dl_pending` 记一笔，等这批跑完自动补一次全的（不补的话那次请求会被静默吃掉）。

### 2.5 阅读进度的写入契约

- 一条记录 = `(album_id, photo_id, page_index, title, cover_url, updated_at)`；同一部漫画的不同话是**多条**，`get_history` 用 `ROW_NUMBER() OVER (PARTITION BY album_id ORDER BY updated_at DESC)` 聚成"一部一条"。
- `page_index` 从 0 开始，前端显示时 `+1`。
- `title` / `cover_url` 是给"最近阅读"卡片用的冗余字段（详情有 24h 缓存，取一次开销小）。
- 写库时机完全由前端决定，见 §4。

### 2.6 推荐（画像 / 候选池 / 打分 / 角标）

一期（2026-10-14，设计稿 `tmp/推荐算法设计.md`）只用**收藏 + 搜索**两种信号，画像**每次现算、不落盘**。

- **画像**（`_taste_profile`）：收藏每部给它的 tag / 作者各 +1.0（快照在 `favorite.tags_json` / `authors_json`；老行回落详情缓存，详情拉回来时 `_backfill_favorite` 顺势补上）；搜索每个词 +0.6 × 次数（`search_log.hits`），关键词**同时当 tag 与作者字符串**参与匹配。时间按 `recommend.half_life_days`（默认 30 天）半衰，各自归一化后只留 top 20 tag + top 10 作者。**隐式反馈（点开详情那档）用户明确砍掉。**
- **候选池**（`_candidate_pool`）：周榜「全部」按观看的前 `recommend.candidates`（默认 40）部，走的就是 `get_ranking` 那套 `ranking:*` 缓存；图源一页条数不定，凑不满再要一页（最多三页）。
- **打分**：`score = (1 - hot_weight) · 匹配 + hot_weight · 热度`，`匹配 = (Σ tag 命中 + author_boost · Σ 作者命中) / sqrt(1 + |tags|)`，`热度 = 1 - 池内名次 / 池大小`。默认 `hot_weight=0.3`、`author_boost=1.5`。
- **候选的 tag / 作者只从本地详情缓存读**（`_cached_names`）：没缓存就算 0 分，**这条路上绝不发请求**。这是"推荐不拖启动"的硬约束：预加载铺详情（§2.1 `prefetch_albums`）攒的就是这份缓存。
- **cold**：画像空、或候选里一个都没命中 → `cold=True`，界面标题写「热门推荐」（不写"为你推荐"，别骗人）。
- **确定性**：同分保持池内顺序、不加抖动 —— 同样的画像 + 同样的池子给同样的结果，否则「换一批」和"刷新一下变了"分不清。
- **落点**：首页 `#/popular` 面板里**第一段**（`board.ts` 把 `createRecommendSection('home')` 插在 `boardMsgEl` 之后、分类横条之前）；搜索页 `#/search` 结果列表**下方**（`kind='search'`，一期与首页完全一致：**不吃本次关键词**）。两处共用 `components/recommend.ts`。
- **「换一批」**：把本段已展示过的 ID 全塞进 `exclude` 再要一批；候选翻完了按钮置灰。
- **跟 hero 去重**（2026-10-14 用户要求）：`exclude` 里还要并上**页面上方已展示过的 ID**（首页 = hero 那三部，经 `createRecommendSection` 的 `shownAbove` 透过来）。后端在打分之前剔候选，所以去重不掉张数。**代价：首页的推荐段要等 hero 请求回来才开铺**（拿不到那三部的 ID 就没得避开），hero 挂掉那条路也照常调一次。`board.ts` 里各分类横条同理（`dropHero()`），详见 §5.17。
- **已收藏角标**：收藏态**不进缓存**，每个列表接口返回前现拼（`_with_favorited` / `_forum_out`，跟现拼封面一个路子）—— 刚收藏完，列表里就该出现新角标。角标只在**真收藏**时才有这个 DOM（没收藏连空位都不留），落在：首页 hero 与分类横条、分类页、搜索页、推荐段、论坛封面条。**收藏页不打**（整页都是收藏、卡片角上已经有删除按钮），详情页保持心形不加角标。

### 2.7 整本离线下载（`download.dir` + `/downloads` 静态根）

- **进度就是磁盘上那些文件**：一张图落了盘才算数。`start_download` 只登记话单（`download_chapter`），
  续传时把「没下完的话 + 标了 done 但磁盘上缺图的话」挑出来补 —— 不看内存里的计数，所以关窗、断电、
  图源抖，下次开窗都只下没下过的部分（`download.auto_resume`，开窗 5 秒后开跑，`_resume_downloads_loop`）。
- **落地位置**：`<download.dir>/<album_id>/<photo_id>/<文件名>`，默认 `~/.jmreader/downloads`。
  `download.dir` 支持 `~` 与相对路径（相对 `~/.jmreader`）。**别把它挪进 `cache/`** —— 那就会被清理删掉。
- **阅读走哪一份**：`get_chapter` 有离线副本就整话返回 `/downloads/...`，并且**不再往 cache 里下第二遍**；
  没有就还是老路 `/images/...`。图片服务因此挂了两个根（`_QuietHandler.extra_roots` 前缀表，
  `translate_path` 里把 `..` 这类片段丢掉，越不出根目录）。
- **失败处理**：单张图重试 `download.retries` 次（默认 3，退避 0.6s×n）；还是失败只把**那一话**标 `error`，
  整本继续（`_pending_chapters` 会把 error 的话再排进来）；用户点「继续下载」时补它。一话内部的图按
  `download.workers` 一批批下，**批间**检查暂停 —— 一次暂停最多多下一批，不然整话下完才停得住。
- **状态机**：任务 `queued` / `running` / `paused` / `done` / `error`；`running` 也算"没下完"
  （上次被关窗打死就停在它上面）。删除（`remove_download`）先置 stop 事件、等 worker 最多 5 秒，
  等不到也照删记录（文件 `ignore_errors` 硬删，Windows 上正被写的那张留给下次）。
- **前端**：详情页「下载」在「阅读」右边同一排（`.detail-actions`），标签跟状态走；只有详情页开着
  且任务在跑时才 2 秒轮一次。我的下载页（`pages/downloads.ts`）有任务在跑时 1.5 秒轮一次，
  **任务集合没变就只改文字**（重建 DOM 会把悬停和下一次点击都打断）。

## 3. 前端契约

### 3.1 启动顺序（改 `main.ts` 前先看这条）

```ts
// 1) 注册路由 + 渲染左侧导航（#nav 是静态 HTML 里的空壳）
// 2) bootSplash()                                   ← 接管 index.html 里内联的闪屏（必须在 nav 之后，落点才有）
// 3) await waitForBridge()                          ← 等 pywebview 把方法真的挂上（不是"对象在"）
// 4) void api.prefetch_home(range, sort)            ← 后台预热首页那批 cache key（不 await）
// 5) document.documentElement.dataset.glass = ...   ← 毛玻璃开关（见 §3.5）
// 6) loadSettings() 之后 splashConfigure(splash)     ← 配置到手再校正时长 / 开关
// 7) startRouter()                                  ← 不等闪屏
```

- **闪屏（`splash.ts`）**：画面本身写死在 `index.html`（HTML + CSS + SVG），`splash.ts` 只管「什么时候揭幕、怎么飞进左上角」。`startRouter()` **不许 await 闪屏** —— 首页在闪屏底下照常铺，揭幕时露出的是成品。`pages/board.ts` 首页铺完（成功或首次失败都算）叫一声 `splashReady()`，闪屏才提前揭幕。
  **品牌行 = 字标 + 「漫画」**：字标落进 `.brand-slot`（`main.ts` 里那格，里面的「孤竹」只是兜底文案），
  右边的「漫画」不碰 —— 用户 2026-10-14 定的落位，见 §5.13。
- **`prefetch_home`**：开窗第一件事就是拿首页那批 key 去图源排队（后端并发跑各分类榜 + 推荐候选池），首页自己来要的时候基本都命中缓存。fire-and-forget，**不许 await**。
- **不要在 pywebview 就绪前开路由**：否则首屏会先闪一下"pywebview api 未就绪"。
- **导航分两排**（`main.ts`）：`NAV_ITEMS` 是内容导航（热门 / 搜索 / 论坛 / 最近阅读 / 收藏 / 我的下载），左下角的 `NAV_FOOT_ITEMS` 是应用级的（关于 / 设置），`.nav-foot` 用 `margin-top: auto` 顶到底；主题开关挂在 `.nav-foot` 里、压在那两个下面。`syncNav()` 走 `navLinks` / `navIcons` 两张 Map —— 分成两排之后就不能再回 DOM 里按 `a[data-path]` 找了（只会找到上面那排）。
- **左下角还有一张「继续阅读」卡**（`resume.ts`）：`createResume()` 返回 `{el, refresh}`，`main.ts` 把它 `prepend` 到 `.nav-foot`、桥就绪后拉一次 `get_history(1)`，之后每次 `hashchange` 再拉一次（同时只跑一个请求）。拿不到 / 还没读过 → 整块 `hidden`。**这里不走 `morphToReader`**：进阅读器时 `body.reading` 会把 `#nav` 整个 `display: none`，源元素在转场中途消失，快照对不上。
- **窄屏（≤1180px）rail 只剩 64px**：`.nav-foot-row` 改竖排，`.nav-theme` / `.nav-resume-go` 的文字也要一起藏（它们的标签是 `<span>`，不像上面那排 `<a>` 那样已经被 `#nav a span` 盖住了，不藏就会竖着折行把导航栏顶破，所以按钮上带了 `title` / `aria-label`），「继续阅读」那张卡整个藏掉。
- `webstatus.ts` 的 `waitForBridge(method='get_settings', timeoutMs=5000, quietMs=800)`：**等具体方法挂上**、**并且离最后一次注入过了 `quietMs`** 才算就绪（每 100ms 轮询 + 监 `pywebviewready` 兜底 —— 事件有可能在开始等之前就派发完了，见下一条）。超时只 `console.error`、**不阻塞启动**（页面自己显示未就绪提示 + 重试按钮）。别退回「只判 `window.pywebview?.api` 在不在」：那是两步注入中间那个**空对象**窗口，见下一条。
- **桥迟到也要能自己接上**：`webstatus.ts` 另给了 `waitForApi(tries=24, gap=500)`（轮询 `window.pywebview?.api`）。页面在 api 还不在时先提示一句、同时盯着它，一就绪自己重来一次 —— `board.ts` / `forum.ts` 已接上，不用用户自己切页回来。
- **pywebview 的桥是"两步注入"的，而且启动那一下会注两遍**（`webview/util.py` 的 `inject_pywebview`，WebView2 每次 NavigationCompleted 都跑）：① `js/api.js` 建 `window.pywebview = {api:{}, _returnValuesCallbacks:{}}` —— **起手就是个空对象，`if (window.pywebview.api)` 判真**；② `js/finish.js` 才 `_createApi(funcList)` 挂方法、把每个函数的 `_returnValuesCallbacks[func]` 重建、最后派发 `pywebviewready`。两步之间要跑 `get_functions(window._js_api)`，**它会 `dir()` + `getattr()` 递归展开 js_api 的每个属性** —— 所以：
  - **别在 js_api 上挂公开的非方法属性**（这条最要命，2026-10-14 真机踩到）：`API.client` / `API.download_dir` 原来都是公开的，一个被展开成 412 个 `client.*`（jmcomic 内部方法，等于白送页面一套内部 API）、一个 300 多个 `download_dir.*`，**而且 `getattr` 会现场把 jmcomic 客户端建出来（连图源，0.85s 起步）**。两步窗口就这么从毫秒被拉到秒级，`_createApi` 还要重建 447 个回调表。改名 `_jm` / `_download_dir`（下划线开头 pywebview 直接跳过）之后：**447 条 / 0.855s → 35 条 / 0.000s**，桥就绪从 1.3~4.8s 变成 **~100ms**。以后往 `API` 上加东西，一律下划线开头。
  - **启动那几百毫秒，这个文档会被注入两遍**：WebView2 会给**两次** NavigationCompleted 各跑一遍 `inject_pywebview`（真窗口探针实测：间隔 50ms ~ 400ms 不等，偶尔只注一遍）。第二遍的 `_createApi()` 里 `_returnValuesCallbacks[funcName] = {}` 是**重建**，把**正在飞的调用**的回调表清掉。Python 侧算完回头 `evaluate_js` 调 `_returnValuesCallbacks[func][id]`，那儿已经不是函数（真机报错：`window.pywebview._returnValuesCallbacks.get_settings.99… is not a function`），JS 这边那个 promise **永远不 settle**。实测过一次：436ms 发出的 get_settings / get_history 撞上第二遍注入 → `await loadSettings()` 再没回来 → `startRouter()` 没跑到 → **整个窗口空白**（不是"少两块"，是啥都没有）。
  - **前端因此有两条纪律**：① 启动闸门 `waitForBridge()` 等**最后一次注入安静下来**再放行。**"最后一次注入"别只听 `pywebviewready`** —— 真机上遇到过桥比我们的脚本先挂好，事件早派发完了，`readyStamp` 停在 0，闸门当场放行、正撞上第二遍（那次 3 个在飞调用全被清）。现在改成看**方法引用变没变**（`noteMount()`：`_createApi()` 每次都 `new Function()` 现造一套，引用一变就是又注了一遍），`quietMs` 取 **800**（实测两遍最多差 ~400ms；等它的代价是 0 —— 闪屏要等 `splashReady` 才揭幕）。② 启动路径上的**读**调用走 `bridgeCall()`（回调被下一次注入清掉会当场判死成 `BridgeLost`，等桥安静再重发；**写接口别用** —— `toggle_favorite` / `save_progress` 这类不幂等，重放等于翻两次）。一次性、不重试的启动动作踩进这个窗口会**静默丢掉**（不报错、不重来）——「第一次进首页没有推荐段 / 没有继续阅读」也是这么来的（两块各自的重试见 §7 第 10 条）。
  - **回归检查**：① 无头 —— `tmp/_check_coldstart.py`（假桥延迟 2s 才挂方法）和 `tmp/_check_bridge_wipe.py`（搬真的 `js/api.js`+`finish.js`，假 Python 端延迟回包，再敲一次 `_createApi()` = 第二次注入 —— 修复前的包两种场景都**整窗空白**，现在是照铺）；② **真窗口** —— `tmp/_probe_bridge.py`（自己起真 pywebview，三路仪器把「注入几次/各在何时、后端何时被调到、`evaluate_js` 送返回值有没有炸」打成时间线；`--dist` 参数改成喂 `frontend/dist` 模拟打包后的样子）。`dev`×3 + `--dist`×2 全绿。**这个 bug 只在真桥的时序里现形，无头假桥抓不全 —— 改了这块务必跑一次真窗口探针。**

### 3.2 路由 / 页面生命周期

- `router.ts`：`registerRoute(path, handler)`，handler 返回一个 `HTMLElement`（被塞进 `#app`，塞之前会 `#app.innerHTML = ''`）。
- 参数走 hash query：`#/album?id=123`、`#/read?photo_id=1&album_id=2`。
- **`onUnmount(fn)`**：当前页注册的收尾函数，路由切走时统一执行（解绑 window 监听、清定时器、存进度都在这儿）。忘了注册就是内存泄漏 + 幽灵监听（`reader.ts`、`popular.ts` 是正面例子）。
- 跳转一律改 `window.location.hash`；"返回"用 `history.back()`。
- **页面状态能进地址栏的就进地址栏**：`history.back()` 只是把 hash 退回去，页面是**重建**的 —— 状态只活在局部变量里，
  返回时就是白页。搜索页踩过这个（`#/search?q=…`，`replaceState` 写入、挂载时按 `params.q` 重搜，见 §5.20）；
  列表页的翻页页码同理（`#/category?c=…&page=3`、`#/forum?page=2`，见 §5.23）——
  挂载时按地址里的页码把前面几页**顺序补齐**。
- **“退回去要落回原处” = 地址 + 页码 + 滚动位置**（§5.23）。碰这条链路时守住三条：
  ① 判“是不是退回来”看 `history.state.__seq` 那枚序号，**别用 `popstate`**（Chrome 在 hash 变化时也发它）；
  ② 页面自己改地址一律走 `router.ts` 导出的 `replaceHash()`，别裸 `history.replaceState`（会把序号章冲掉）；
  ③ 滚动位置在 `resolve()` 开头记一次，键用 `currentKey`（屏幕上这一页的地址），别用 `location.hash`、也别等下一帧。
- `pages/downloads.ts`（我的下载 `#/downloads`）：列 `get_downloads`；卡片副标题 = 下载进度 + 「最近阅读」那份阅读进度（后端现拼的 `read`），封面右上角进度角标，卡片下面「暂停 / 继续 / 删除」。有任务在跑时 1.5 秒轮一次（`onUnmount` 停表），**任务集合没变就只改文字不重建 DOM**。
- `pages/forum.ts`（论坛 / 全站评论流）：分页拉 `get_forum`，翻到底靠 `has_more`；每条评论的封面条先显示 `JM<id>`，随后 `get_album_titles` 把标题补上（**不是每页必成功，失败就继续显示 ID**，所以别把它当关键路径）。切走之后晚回来的请求靠页面里的 `alive` 标记丢掉。
- `pages/about.ts`（关于 `#/about`）：**纯静态的说明书页**，入口在导航栏左下角。只有三块——能干什么 / 怎么用 / 数据在哪，是 README 的"用户视角精简版"（改特性时两边一起改）。**别在这里加外部链接**：这个壳没做 `target=_blank` / `webbrowser`，点出去是把当前页顶掉、回不来。
- 榜单板（首页 + 分类页）共用 `pages/board.ts` 的 `boardPage(分类)`：结构固定是 **hero（当前分类前三）+ 分类标签条 + 面板**；`pages/popular.ts` / `pages/category.ts` 只是两行包装。面板里铺什么由分类决定——`all`（首页）铺"别的分类各一行"，具体分类则铺它自己的整页列表。
- **预热**（`prefetch.ts` + 后端两个 `prefetch_*`）：列表铺完把"这一刻摆在屏幕上的"本子送去预热详情缓存；详情页把"阅读按钮要打开的那一话"送去下开头几张；阅读器页码过了 `prefetch.next_at`（默认 90%）再把下一话的开头排队。全是 fire-and-forget，**不许 await、不许挡界面**；条数 / 张数上限在后端（`prefetch.albums` / `prefetch.chapter_images`，重启生效）。
- `window.addEventListener` 是全局的：页内 scroll/keydown/wheel 监听**必须在 `onUnmount` 里解绑**（`reader.ts` 还加了一层 `if (!document.contains(el))` 兜底自解绑）。

### 3.4 设计 token（`style.css` 顶部 `:root`）

- 层级靠**表面阶梯 + 1px 发丝线**，不靠投影（`--shadow` 只给浮层：下拉、底部浮层、toast）。
  例外是 `album-card`：鼠标悬浮时 `translateY(-4px) scale(1.06)` + 背景往上一格（`--surface-3`）+ `--shadow-card`（用户点名要的"抬起来"手感；暗底上单靠投影看不出来，所以三样一起给）。
- 主操作 = `--action`（白底黑字，全站唯一实心按钮）；强调色 `--primary`（#57c1ff）只给加载 / 焦点 / 阅读进度，**不当装饰用**。
- 布局：`--rail`（左侧导航宽 208px）、`--col`（内容列 960px，左右各一条边界线）、`--col-pad`（列内留白 20px）；`body` 有 `padding-left: var(--rail)`。
- 设计语言出处：awesome-design-md 里的 Raycast DESIGN.md（暗色分层 + 发丝线 + 键帽）；动效参考 morphicons。
- **动效总则（2026-10-14 加）**：会动的只有 `transform` / `opacity`（唯二例外是主题圆揭示与卡片悬浮的观感需要，见 §5.14）；
  时长/曲线走 `--ease-spring: cubic-bezier(.34, 1.56, .64, 1)` + `--dur-fast/.--dur/--dur-slow`；所有按钮 `button:active { transform: scale(.96) }`。
  材质走 `--depth-1/--depth-2`（近影 + 远影两层）+ `--edge/--edge-strong`（1px inset 高光）；加载态统一是 `--dots` / `--dots-ink` 网点 + `ink-flow` / `ink-pulse`。

### 3.5 毛玻璃开关

- 后端 `window.glass`（none/mica/acrylic/tabbed）+ `window.glass_opacity` 决定 **DWM 那层**。
- 前端启动时读配置，给 `<html>` 打 `data-glass="on"`；`style.css` 里 `:root[data-glass="on"]` 把画布系列变量换成半透明值，让系统模糊透上来。
- 两边必须一致：**后端没开 DWM 亚克力时，前端就不该留透明度**（否则是"透着一层没模糊的桌面"，比不透明更难看）。所以 `glass: none` 时前端会把变量换回不透明。

### 3.6 主题（暗 / 浅）+ 动效入口（`theme.ts` / `motion.ts`，2026-10-14）

- **两套变量，一套名字**：`:root` 是暗色（默认），`:root[data-theme="light"]` 是浅色，变量名一一对应；组件样式只管用变量。
  浅色那套**必须排在 `:root[data-glass="on"]` 后面**（权重一样，靠顺序定胜负），毛玻璃 + 浅色还有一条 `:root[data-theme="light"][data-glass="on"]`。
- **主题只记在本机**（`localStorage` 的 `guzhu:theme`，JSON 串），不进 `config.yaml`。**第一帧之前**由 `index.html` 里一段内联脚本读它并打 `data-theme` ——
  交给 `main.ts` 会晚（要等 pywebview 桥），浅色用户会先闪一下暗色。两边读的 key 格式必须一致（`store.ts` 的 `saveState` 写的是 `"light"` 这种带引号的 JSON）。
- **切主题 = 从点击处摊开一个圆**（View Transitions + `clip-path: circle()`）：`theme.ts` 的 `setTheme(origin, next)` 直接吃 `MouseEvent`（用指针坐标）或元素（用中心）。
  入口两处：左侧导航底部的 `.nav-theme`、阅读器设置浮层里的「界面主题」（阅读时导航是隐藏的，所以两处都要）。
- **封面 → 阅读器是共享元素转场**：`motion.ts` 的 `morphToReader(coverEl, hash)`；详情页「开始阅读」和章节条目都走它。
- **`prefers-reduced-motion`**：`calmMotion()` 一为真就完全不碰 View Transitions，直接落值（换主题 / 跳章节都照常，只是没有过渡）。

## 4. 阅读器（`pages/reader.ts`）—— 全项目最脆的一块

### 4.1 页面结构

顶部信息条（返回 + 标题/页码 + 自动滚屏键）+ 常驻 2px 进度线 + 底部胶囊操作条（上一话 / 目录 / 下一话 / 设置）+ 数字格子目录浮层 + 阅读设置浮层 + 话末"下一话"卡片 + toast。两条工具条默认隐藏，鼠标动一下（位移 > 6px）才出现，停手 2.6s 收起；**滚轮和方向键不算唤出**（不然翻页时一直闪）；点图片中间区域手动收/放。

### 4.1.1 两个浮层怎么开怎么关

- 目录 / 阅读设置共用一个"同时只开一个"的约定（`openSheet(name)`，`name=null` 就是全关），两个按钮自己 toggle。
- **点浮层外面 = 关浮层**，由 `document` 上一个冒泡期的 `click` 处理（`onOutsideClick`，`onUnmount` 里解绑）。两处细节别改：
  - **要放过 `.chapters-btn` / `.settings-btn`**：它们自己会切 / 开关，让外面这一手再插进来，「目录 → 设置」会先切成设置、紧接着又被判成"点了外面"给关掉；
  - 图片区那个 handler 里也要先 `if (sheetOpen()) { openSheet(null); return }` —— 那一下只用来收面板，不能顺手翻页 / 收工具条（document 上那个是兜住图片区之外的地方，比如内容四周的留白）。
- 面板开着时滚轮让给面板：单页模式下滚设置面板会把后面那页翻掉，`onWheelFlip` 里加了 `sheetOpen()` 短路。
- `Esc` 也是先收面板、再按一次才退出（这条更早就有了）。

### 4.2 进度相关状态机（**这一堆一行都别乱动**）

| 变量 | 含义 |
|---|---|
| `progressReady` | 上次进度已从库里读出来。**false 之前 `currentIndex` 是无意义的 0**：不写库、不认滚动 |
| `restoring` | 正在把版面钉回上次那一页，期间页码只是过渡值，不写库 |
| `restoreCancelled` | 用户自己翻页/滚动了，放弃还没执行的恢复 |
| `ownScrollY` | 我们自己 `scrollIntoView` 之后的滚动位置，用来在 scroll 事件里区分"我们滚的"和"用户滚的" |
| `lastLayoutChangeAt` | 上面的图到货把版面撑开的时刻（浏览器会顺带修正滚动位置） |
| `userInputAt` | 用户真的动手了（wheel / touchmove） |
| `savedKey` | `photo_id:index`，同一页只写一次库 |

### 4.3 三条退出路径都要落进度

```text
返回按钮 / Esc / 话末"返回详情"  ──► flushProgress() + history.back()
路由切走（onUnmount 收尾）        ──► flushProgress()
关窗口 / 刷新（pagehide）          ──► flushProgress()
```

`flushProgress()` 是退出专用入口：它允许在 `restoring` 期间按**屏幕上实际显示的那一页**写一次（正常路径下 `restoring` 期间是禁止写的）。

### 4.4 恢复进度的坑（"二次进入又回到第 1 页"）

- 图还没到货时文档很矮，`scrollIntoView` 会被浏览器夹回顶部 → 所以 `restoreScroll()` 是**边滚边等**：每当前面的某张图到货、目标页位置变了，就重新钉一次，直到目标之前的图全部就位（或 20s 超时 / 用户自己动了）。
- 恢复期间的 `scroll` 事件**不能**当成用户滚动，否则会把过渡页码写进库，把真进度抹掉。

## 5. 踩过的坑（症状 → 原因 → 结论）

### 5.1 pywebview 透明窗口：窗口"消失"

- **症状**：`transparent=True` 的窗口，在 `webview.start(func=...)` 里改窗口属性后，窗口彻底不显示；`EnumWindows` 能看到它存在，但 `IsWindowVisible == False`，页面也从没开始加载。
- **原因**：pywebview 的透明窗口（Chromium 后端）建窗时是 `Show()` → `Hide()`，真正显示要等 WebView2 触发 `NavigationStarting`（见 `webview/platforms/winforms.py` 里那句 "hack to make transparent window work"）。抢在这个缝隙里改 Form 属性，会把窗口永久留在隐藏态。
- **结论**：等 `window.events.loaded`（页面加载完）**并且** `IsWindowVisible(hwnd)` 为真再动手；等不到就什么都别做。实现见 `backend/glass.py`。

### 5.2 WinForms 属性只能在 UI 线程改

- **症状**：跨线程 `form.Opacity = x` / `webview.DefaultBackgroundColor = ...` → `InvalidOperationException: CoreWebView2Controller members can only be accessed from the UI thread`（有时静默失效）。
- **结论**：`from System import Action; form.BeginInvoke(Action(fn))`，把改动丢回 UI 线程（pythonnet 能把 Python 函数转成 `System.Action`）。
- 附带：`form.BackColor = Color.FromArgb(0,0,0,0)` 抛"控件不支持透明的背景色"；pywebview 自己走的是 `SetStyle(ControlStyles.SupportsTransparentBackColor, True)`，别手动设 BackColor。

### 5.3 系统亚克力要 Win11 22H2+，失败就别压透明度

`DwmSetWindowAttribute(hwnd, 38 /* SYSTEMBACKDROP_TYPE */, ...)` 在 Win10 上返回非 0。此时若还把窗口整体压到 92% 不透明，得到的是"透着一层没模糊的桌面"。所以 `_dwm()` 返回是否成功，**只有成功才设 `Form.Opacity`**。

### 5.4 首次进章节总是第 1 页

图没高度 → `scrollIntoView` 被夹回顶部。见 §4.4。

### 5.5 关窗口太快，进度没落库

**别做防抖**：原来 1s 防抖 + `pagehide` 里发个异步桥调用，窗口关得快就都没赶上。现在翻页即写（同一页靠 `savedKey` 去重），`pagehide` / `onUnmount` 再各补一次。

### 5.6 "同一部漫画每看一话就多一条记录" + "最近阅读里进度不更新"

- 记录粒度是 `(album_id, photo_id)`（一话一条），展示时用窗口函数按 album 聚合成一条。
- "看完退出去历史里进度还是旧的"：退出路径没落库 —— 三条退出路径都挂 `flushProgress()`（§4.3）。

### 5.7 图源细节（都踩过）

- **标题 / 标签可能为空**：章节标题空了要退回 `第 N 话`；`tags` 空数组别渲染空标签。
- **域名会变**：jmcomic 的 `FLAG_API_CLIENT_AUTO_UPDATE_DOMAIN` 在建 client 时自动更新 API 域名（控制台那行 `api.update_domain.success` 就是它）。所以**永远不要缓存绝对图片 / 封面地址**：封面用 `JmcomicText.get_album_cover_url(album_id)` 现拼，章节图 URL 用 `img_base` 现拼。
- **临时文件名要保留原后缀**（§2.4）。
- **预加载那条路要自己建 `images/<photo_id>/` 目录**：`get_chapter` 会建，jmcomic 自己不会 —— 目录不在，`download_by_image_detail` 是"静默不落盘"（请求照发、异常照吞、磁盘空），症状是"日志里图都请求了，一张也没落盘"。
- **代理**：本机 mihomo 在 `127.0.0.1:7890`，`JmOption.default()` 的 postman 里已经配好 `proxies`（`client.postman.meta_data.proxies`）。改网络相关代码时别忘了这层。
- `--disable-features=ElasticOverscroll` 是 pywebview 自己加的，别重复加 `AdditionalBrowserArguments`。

### 5.8 前端小坑

- **详情页封面喂给 CSS `url("...")` 前要把 `"` 转义**（换成 `%22`），否则图源标题里的引号会把 CSS 拆坏。
- **所有来自接口的文本都走 `textContent` / `escapeHtml`**（作者名里真有 `&`、`<`）。
- **`<input type="number">` 默认 `step=1`**：要填 0.92 这种小数，字段定义里必须给 `step`（否则浏览器判 `:invalid`，上下键也按 1 跳）。
- **路由首屏别渲染两遍**：`startRouter()` 在没有 hash 时是赋 `#/popular` 触发 `hashchange`，**不要**再监听 `DOMContentLoaded`（`reader.ts` 那套进度逻辑最怕这个）。

### 5.9 Windows 下的写文件 / 命令坑

- 项目里的文本文件都是 **UTF-8 无 BOM + CRLF**。用 Python 改文件时要 `newline='\r\n'` 写（或先探测原行尾）；PowerShell here-string 同理。
- **含中文的 `.ps1` 必须存成带 BOM 的 UTF-8**，否则 Windows PowerShell 按 ANSI(GBK) 读，中文变乱码连语法都过不去。省事点：脚本写成 `.py`，用 venv 的 python 跑。
- 这份环境里**没有 `apply_patch`**：改文件用 `[IO.File]::WriteAllText(...)` / here-string / Python 脚本。
- **5173 是用户的 vite dev server，别占用**。
- 测试用的 pywebview 窗口用完要关（`PostMessageW(hwnd, WM_CLOSE)` 或 `taskkill /T /PID`），别留孤儿进程；别 `Stop-Process chrome` 一把梭（会误杀用户浏览器）。

### 5.10 首屏"加载不出来" / 论坛"是空的"（2026-10-14 修）

- **症状**：开窗后第一次进首页整页像没加载出来，论坛点进去是空的；切到别的页再切回来就好了。
- **原因一**：`API.__init__` 里建 jmcomic 客户端（连图源 / 更新域名 / 拉 `/setting`）会**挡着开窗**，窗口十几~几十秒后才出现。→ 客户端改成懒加载 + `_warm_client` 后台预热（见 §2.1）。
- **原因二**：`.board-panel .reveal album-card` 的"虚化入场"是 `opacity:0; filter:blur(10px)` 起手，全靠 `IntersectionObserver` 给区块加 `.in` 才亮；而**窗口没在画的时候（刚创建还没画第一帧 / 被别的窗口整个盖住 / 最小化）IO 不回调**，卡片就一直是透明 + 模糊 = 看着像"页面没加载"。→ 挂完 observer 之后另用 `setTimeout`（400ms / 1500ms）自己量一次 `getBoundingClientRect()`，在视口里的直接加 `.in`（`board.ts` 的 `revealSoon()`）。**以后凡是"进场动画当门帘"的写法，都要配这种兜底。**
- **原因三（实测）**：隐藏窗口里 **CSS 过渡的时钟是停的** —— `.in` 明明加上了，`getComputedStyle` 算出来还是 `opacity: 0`；窗口 `show()` 之后过渡接着走完（0 → 1）。所以**别拿"算出来的 opacity 还是 0"当"类没加上"的证据**。
- **原因四**：首屏任何一处失败以前会把**整页**带进 `error`（hero 那一次请求挂了，下面各分类一个都不铺）。→ 一律降级 + 自愈：hero 挂了只占 hero 那一条（给句子 + 重试按钮），各分类各自重试一次，整页 / hero 失败自动重试 2 次（1.2s、2.4s），窗口回到前台（`focus` / `visibilitychange`）时补亮未入场的区块、页面还挂在错误上就自己重来一次。

### 5.11 推荐 / 收藏态（2026-10-14）

- **跟本地状态走的字段别进缓存**：`album:v2:`（24h）、`ranking:*`（1h）里要是带上 `favorited`，取消收藏后列表还显示"已收藏"。→ 一律返回前现拼（`_with_favorited` / `_forum_out`），缓存里**没有**这个字段。
- **搜索记录别放回 localStorage**：推荐要"次数 + 时间"，前端那份只有关键词。搬进 `data/app.db` 的 `search_log`（主键 `keyword`，`COLLATE NOCASE` 去重，表最多 200 条）。
- **推荐不许发请求**：tag / 作者只读本地详情缓存，没缓存按 0 分算。想提高命中率就调 `recommend.candidates`，或让预加载多铺几部详情（`prefetch.albums`）——**别改成现拉详情**，那会把首页启动拖回十几秒。
- **给 `favorite` 表加列要兼容老库**：`tags_json` / `authors_json` 是后加的，走 `_ensure_columns()` 的 `ALTER TABLE ... ADD COLUMN`；老行先回落详情缓存，`get_album_detail` 拉新数据时 `_backfill_favorite` 补上。
- **收藏页的角标是故意不打的**（整页都是收藏 + 卡片角上已有删除按钮）；`album-card` 的角标 `pointer-events: none`，别让它挡住卡片的点击。

### 5.12 整本下载（2026-10-14）
- **一次都没下过的人进来盯着 4 张骨架卡片**（2026-10-14 用户报的）：`downloads.ts` 为了"任务集合没变就别重建 DOM"，用 `renderedIds` 记住上次画过的 id 串；它起手写的是 `''`，而空列表算出来的 ids **也是** `''` —— 第一次 `sync()` 就以为"这一屏画过了"，于是永远不去铺空态，加载时那 4 张 `renderAlbumSkeleton` 就留在原地一直呼吸。起手必须是 `null`。**同类优化记得挑一个不可能是真实值的哨兵。**

- **`photo_id` 不是本地表的主键**：`download_chapter` 用的是 `(album_id, photo_id)`（跟 `history` 一个规矩）。
  "photo_id 全站唯一"只是图源的约定，拿它当主键的话，两本撞 ID 时第二本的章节会被 `INSERT OR IGNORE`
  静静吃掉（测试里就这么翻过车：整本的话数变成 1）。
- **离线副本别放 cache**：`clear_cache` / `cleanup_cache` 只碰 `cache/`，用户下的东西必须在 `download.dir` 里，
  否则「整理缓存」就把整本离线下载删了。
- **图片服务要挂两个根**：`/images` → `cache/images`、`/downloads` → `download.dir`。只服务 cache 的话，
  下载完的章节阅读器读不到（`translate_path` 是唯一能换根的地方，`..` 片段要丢掉）。
- **下完的话别再往 cache 里下**：`get_chapter` 命中离线副本时**不要**再走 `_spawn_download`，
  否则同一话下两遍（第一版就是这么写的，磁盘翻倍）。
- **下载页的按钮别压在封面角上**：卡片只有 148px 宽，角上塞两个按钮会跟进度角标挤成一团（截图才看出来）。
  现在按钮在卡片下面那一排，进度角标留在封面右上角。
- **毛玻璃下 `--bg` 是半透明的**：详情页标题 / 作者 / 观看收藏数 / 标签要垫底就得写死颜色（`#07080a` /
  `#141516`），用 `var(--bg)` 等于没垫 —— 背后那层虚化的封面照样透上来。

### 5.13 开场闪屏（2026-10-14）

- **闪屏必须内联在 `index.html` 里**：dev 态模块图那几百 ms 里 `main.ts` 根本还没执行，放 JS 里画就是「先白一下再开始描字」。所以 HTML + CSS + SVG 全内联，不引 JS / 字体 / 图片。
- **字标用手画单线 SVG path + `stroke-dashoffset` 描边**：普通字体转 path 出来的是**轮廓**，含孔的字母（u、h）会「先描外圈再描内圈」。6 段 path 各带 `pathLength="1"` 和自己那串 `animation-duration / animation-delay`，加起来 1000ms。
- **落位用 FLIP（WAAPI），不用 View Transitions**：MDN 写明调用期间文档 `hidden` 会整个跳过，而 pywebview 启动期恰好可能不可见。FLIP 量首末矩形 → 反向 transform → 播 → 交棒静态 DOM；`transform-origin` **必须显式写 `top left`**（SVG 默认变换原点不是左上角，不写飞行就是斜的）。
- **导航里那份字标是从闪屏那份 `cloneNode` 来的**：路径数据只有一处，改漏不了；克隆完去掉 `id` / 内联 `style`（导航里要静态的，不要描字动画），先 `visibility: hidden` 占住位置 —— 免得「两个 GuZhu」同框。
- **落位定稿（2026-10-14 用户定）**：字标只取代品牌行里的「孤竹」两字，品牌行 = `[字标]漫画`，下面 `Guzhu Comic` 不动。
  落点因此是 `.brand-slot`（不是整行 `.brand-mark`），`placeNavMark()` 只清那一格。
  导航里字标 **76px**（原 88px）：`#nav` 只 208px，88px + 两个字会超出一格、把「漫画」挤成竖排；
  76px 的大写高 ≈ 15px，跟旁边 15px 的「漫画」齐平，`.brand-mark` 上加 `white-space: nowrap` 兜住折行。
- **预热只有一条原则：复用首页那批 cache key**。`get_ranking` 加了 `_fetch_guard`（同一把 key 同一时刻只让一个线程去图源），预热和首页自己那次请求撞上时不会重复拉。
- **并发数必须够铺满所有分类**：一开始 `ThreadPoolExecutor(max_workers=4)`，7 个任务排两批，首页反而比不预热还慢；改成 `max_workers=min(8, 任务数)` 才是一批跑完（实测首页 512ms，命中缓存 9ms）。
- **时长**：描字 1500ms + 停留 450ms = 最短 1950ms，`splash.max_ms`（默认 3000ms）硬揭；点一下 / `Esc` 跳过；`prefers-reduced-motion` 跳过描字与飞入。`min_ms` / `max_ms` 在设置页「启动」组里；**描字那 1500ms 是两处写死的**：`index.html` 里 6 条 `animation-duration` 的和、以及每条自己的 `animation-delay` 累加值，必须都等于 `splash.ts` 的 `DRAW_MS` —— 改快改慢这三样一起动。
- **开窗那一下的白**：`main.py` 显式传了 `background_color="#07080a"`（pywebview 默认白，窗口在导航开始时就 show），但**毛玻璃开着时（`transparent=True`）pywebview 会忽略它**（`winforms.py`），那条路得真机看。兜底是 `hidden=True` + 稍后 `show()`，但那跟「秒开」是交易。

- **字标几何（2026-10-14 二稿）**：笔画 25；大写顶中心 y=62 / x 高顶中心 y=100 / 基线中心 y=189；viewBox **紧贴字身**（`23 45 637 161`，四周只留 4.5 余量）—— 一稿的 `0 0 590 240` 里字只占 74%×49%，一放大就发现全是死白。闪屏 `min(56vw, 620px)`、导航 `.brand-logo` 88px。

### 5.18 健壮性审计：漏洞 / 崩溃点（2026-10-14）

### 5.23 「进详情再返回」落回原处：滚动位置 + 列表页码（2026-10-14）

用户报的现象：搜索里点进详情、再点「返回」，回来**位置在顶部**（结果还在，但看不到刚才那批）；分类页 / 论坛翻了页再进详情，
返回后**退回第 1 页**。这轮把两件事一起做了（同批还有 ② ③，见 §5.24 / §5.25）。

**口径**：只有"从历史里退回来 / 退到前面"才算"回到原处"；点左侧导航去别的页是**新的一趟**，照旧从顶部看起。
位置记忆**只活在这一次会话**（`scrollMemo`，上限 60 条）—— 刷新 / 重开窗口从头看是正常预期，不落盘。

**四个坑（都实测过，写在这儿省得下次再踩）**：

1. **`popstate` 不能用来判"是不是退回来"**：Chrome 在 **hash 变化时也会派发 `popstate`**（跟 `hashchange` 前后脚，时间戳都一样），
   于是"点导航进新页面"也被当成退回来 —— 位置就留在上一页那儿不动（实测 nav 之后 `scrollY` 还是 500）。
   改成**自己给每条历史记录盖递增序号**：`history.replaceState({__seq: n})` 盖在 `resolve()` 之后，
   `hashchange` 时读 `history.state.__seq` —— **目标序号 ≠ 当前序号 = 历史穿梭**（前进 / 后退都算），
   **= / 没盖过 = 页面自己写 hash 推出来的新条目**。
2. **裸 `replaceState` 会把序号章冲掉**：页面把页码写进地址时用的是 replace，`history.replaceState(null, '', next)` 带了个 `null`，
   `__seq` 就没了 —— 之后再"退回来"认不出这条记录，页码能对上、滚动位置直接丢。
   所以 `router.ts` 导出 **`replaceHash(next)`**：`replaceState(window.history.state, '', next)`，顺手把 `currentKey` 也搬到新地址。
   **页面自己改地址一律走它。**
3. **位置要在"离开页面的那一刻"记**，别指望滚动监听：Chrome 的 `scroll` 事件是"下一帧派发"，headless 探针里整轮**只派发了一次**；
   而一开始把它塞进 `requestAnimationFrame` 里连位置带地址一起读，那一帧被拖到 900ms 之后 —— 页面早换完了，
   位置就记到**新页面**名下（memo 里出现 `'/album?id=…' → 0`，搜索页那条压根没有）。
   现在 `resolve()` 开头（`traversed` 已取走、页面还在、位置没被搅乱）用 `currentKey` 记一次保底，`scroll` 监听也记、同样用 `currentKey`。
4. **地址会在挂载途中变脸**：分类页 `load()` 里 `page = 0` 之后有一句 `syncPage()`（本来是给"换榜单条件"用的），
   会把地址里的 `&page=3` 先摘掉、数据回来再补上。所以还原用的键要在**挂载前**量好 —— 代码里就是 `resolve()` 那个 `const targetKey = keyOf()`。
   踩的时候症状很迷惑：`traversed` 是 true、memo 里明明有 600，可 `restoreScroll` 收到的是 0（键被换成了不带 `page` 的那条）。

**实现（`frontend/src/router.ts`）**：`scrollMemo` + `currentKey` + `rememberScroll()`（`keyOf()` = `parseHash()` 的 path 加**排序后的参数**）；
`readSeq()` / `stampSeq()` 管那枚序号；`history.scrollRestoration = 'manual'`（浏览器自己那套滚动还原会在 hash 切完之后动手，把我们那下顶掉）；
`restoreScroll(target)` = `setTimeout` 起手 + 120ms 最多 20 次重试（页面是"先骨架后数据"长出来的）+ 用户一滚轮 / 一触摸就放手。
阅读器（`/read`）两边都不管：它有自己的"回到第 N 页"（§4.4）。

**列表页侧**：`boardPage(分类, startPage)` / `forumPage(params)` 读地址页码（`pageParam()`，认不出 / 越界当 1），
挂载时顺序补齐前面几页（榜单每页都在后端缓存里，这几下是命中缓存）；翻页就 `syncPage()` → `replaceHash()` 写回地址。

**顺手修掉的两个真 bug（都在同一条链路上）**：

- **分类页第一次点「加载更多」会把第 1 页再要一遍**：`load()` 里只 `page = 0`、拿完第一页没置 1，于是"加载更多"要的是 `page + 1 = 1` ——
  卡片重复 + 页码整体错一位。现在拿到第一页就 `page = 1`（top 只 `slice(3)` 进列表，不会重复）。
- **搜索页 `syncUrl()` 只写 `q`**：从详情点标签 / 作者进来（`#/search?q=X&scope=tag`）再返回 / 刷新，会按 localStorage 里
  "上次用的条件"重搜，结果跟当时那批对不上。现在非默认值才追加 `&scope=` / `&sort=`。

**回归**：`tmp/_check_back_restore.py`（无头 Chrome + 假桥 + dist 副本；探针走外部 `probe.js` + `fetch('/report?d=…')` 回报，
假桥的 `Proxy` 记得 `then → undefined`）—— **19/19 ALL PASS**：A 搜索→详情→返回（地址 / 结果 / 滚动 500）、
B 分类页翻两页→详情→返回（`page=3` / 33 张 / 滚动 600）、C 论坛翻页→详情→返回（`page=2` / 10 条 / 滚动 500），
外加一条对照面「点导航进新页面要回顶部」。真窗口冒烟 `tmp/_probe_bridge.py --dist` 也过（`injects` 1 次、`returnValueFAIL` 空）。

**别做**：别把 `popstate` 请回来当判据；别让页面自己 `history.replaceState(null, …)`；别把滚动位置落盘。

  **C 组（多图源、换 HTML 客户端做"只看汉化"、登录类：收藏夹同步 / 签到 / 发评论 / 里番）不做，以后也不做。**
- **踩到的坑**（都在这儿了）：
  - `API` 上的公开属性会被 pywebview 递归展开 → **新加的东西一律 `_` 开头**（见 §7 第 11 条）。
  - `start_download` 原来直接拿传进来的标题 `INSERT OR REPLACE`：阅读器 / 章节行点「下载这一话」不带标题，就把已经存好的本子名
    **抹成 `漫画 422866`**。现在没带标题 / 封面就沿用库里那份。
  - 速度采样必须**按 album 分桶**（`_dl_bytes` / `_note_bytes` / `_dl_speed`，30 秒滑窗）：整本下载与单话下载共用同一个下载器，
    混在一起算速度会跳。
  - 静态服务原来启动时定死根目录 → 热更装完得重启。现在 `translate_path` **每请求重挑根**（`~/.jmreader/web` 有 `index.html` 就用它），
    所以装完 `location.reload()` 即生效。
  - 托盘 / 通知走 WinForms 的 `NotifyIcon`（pywebview 里拿得到 `Form`），**零新依赖**；全局快捷键得自己用 ctypes 起消息泵线程
    （`RegisterHotKey` 的 `WM_HOTKEY` 只发给注册它的那个线程）。改 WinForms 属性只能在 UI 线程（见 §5.2）。
  - 更新地址白名单：`_check_url` 只认 https，`http://127.0.0.1` 是唯一例外（给回归脚本的假发布端用）。
- **回归**：`tmp/_check_updater.py`（39 项）、`tmp/_check_backend_apis.py`（83 项）、`tsc --noEmit`、`npm run build`、
  真窗口 `tmp/_probe_bridge.py --dist`（injects 1 次 / `returnValueFAIL` 空 / 推荐段 10 卡）。

### 6.6 可以"减代码"的地方（不是新功能）

- `_TIME_MAP` / `_CATEGORY_MAP` + `categories_filter` → 可换成 `day_ranking` / `week_ranking` / `month_ranking`（它们的 `category` 直接吃 `'0'` / `'doujin'` / … 这套字符串，和现在的映射值一致）。

## 8. 改代码时的纪律

- 改前端必跑 `tsc --noEmit`（`noUnusedLocals` 开着，留个没用到的变量就报错）。
- 后端加接口要同步 `frontend/src/pywebview.d.ts`。
- 列表接口里"跟本地状态有关"的字段（收藏态这类）一律**返回前现拼、不进缓存**；缓存只放"跟本地无关、只跟时间有关"的东西。
- 注释写"为什么"（踩过什么坑），别写"是什么"。
- 提交前用真窗口（`main.py`）过一遍：首页 → 搜索 → 详情 → 阅读（滚到底）→ 返回 → 最近阅读 → 设置。

**要什么**：以后改前端不用重新打包 exe、也不用给用户发新安装包。exe 里那份 dist 冻结在打包那一刻，
热更下来的那份放 `~/.jmreader/web/`，静态服务每请求先看它、有就用它（`translate_path`，见 §5.26），装完刷新页面即生效。
**不碰 exe、不自替换** —— `tmp/打包分发设计.md` §8 说的"不做自动更新"指的是 **exe 自替换**，跟这条不冲突
（`backend/updater.py` 顶部注释也写了这一层区分）。

### 9.1 发一次版（发版的人）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\publish_frontend.ps1
```

`npm run build` → 打 `frontend-dist-<构建号>.zip`（`includeBaseDirectory=$false`，zip 里就是 dist 的内容）→ 算 sha256 →
写 `manifest.json`。两个产物都在 `web_dist_out/`（这个目录已进 `.gitignore`）。把它们传到更新地址
（默认 `code.guzhujushi.cn` 上 `guzhu_comic` 仓库的 `web/` 目录）就完事了，客户端下次开窗自己会看到。

`manifest.json` 字段：

| 字段 | 意思 |
|---|---|
| `version` / `web` | 前端构建号（`20261014-2129-4f05b0d` 这种：日期-时刻-短提交号）；客户端 `get_version().web` 比的就是它 |
| `app_min` | 需要的最低**安装包**版本；比客户端新就报 `too_new`（只能去下新安装包） |
| `notes` | 更新说明：设置页摊开显示，右下角提示条挂在悬停标题上 |
| `published_at` / `file` / `size` / `sha256` | 发布时间、zip 文件名、字节数、sha256（客户端下完**必须**对一遍） |

### 9.2 客户端这一侧（`backend/updater.py`）

1. `check()`：拉 manifest → 比版本 → 顺带报 `too_new` / `known_bad`；**从不抛异常**（原因写进 `error`，界面安静地不提）。
2. `apply()`：下载 zip 到临时目录 → 校验大小与 sha256 → **白名单解压**（后缀只放行 `.html/.js/.mjs/.css/.json/.txt/.map`
   与图片 / 字体；zip 里出现 `.exe/.bat`、路径穿越、体积超标一律拒）→ 整目录替换 `~/.jmreader/web`（旧那份挪成 `web.old`）→
   校验 `index.html` 引的 `assets/*` 都在。
3. **自动回滚**：装完先 `mark_boot()`，前端起来后调 `notify_booted()`；30 秒（`BOOT_WATCH_S`）没报到 —— 页面白着、脚本炸了 ——
   下次开窗 `review_boot()` 会把这份前端撤掉、退回 `web.old`，并把版本记进**坏版本名单**（`known_bad`，界面上不再劝装）。
   `web.old` 也没了就直接退回"出厂那份"。
4. `rollback()`：设置页「退回上一版」手动走同一条路（`forget_boot` 保留坏版本名单）。
5. 关掉通道或换地址：`config.yaml` 的 `update.enabled` / `update.url`（地址也可以直接给到 `.json` 全路径）。
   **通道开着但仓库还没建**（404）时，`check_update` 只是 `error`，界面什么都不显示 —— 不会拿这个烦人。

### 9.3 前端这一侧

- `main.ts`：桥就绪 → `notify_booted()`（**别删**：删了以后更新出问题就只能手动去删 `~/.jmreader/web`）；
  `update.auto` 开着时 2.6 秒后查一次，有新版在右下角挂一条提示 —— **只提示，装不装由用户点**。
- `pages/settings.ts`「更新」块：检查 / 立即更新（装完自动刷新）/ 退回上一版 / 打开前端目录。
- `pages/about.ts`「版本」小节：版本行 + 检查更新 + 打开日志目录。
