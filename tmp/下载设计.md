# 整本离线下载（B3）设计稿 — 2026-10-14

> 目标：详情页一键「下载」整本 → 左侧导航多一个「我的下载」；下载断了（关窗 / 关进程 / 图源抖）
> 下次开窗按已有进度接着下，不重头来；下载目录写进 `config.yaml`。

## 1. 需求拆解（用户原话 → 落地）

| 用户原话 | 落地 |
|---|---|
| 左侧导航栏加入我的下载 | `main.ts` 的 `NAV_ITEMS` 加 `/downloads`，「我的下载」页 `#/downloads` |
| 详情页加入下载选项，和继续阅读做到同一排 | `.detail-actions` 一行两格：`继续阅读` + `下载`（下载按钮随手改标签） |
| 下载后进度和最近阅读里的进度一样 | 我的下载卡片副标题 = **同一份 `history` 表的「读到第 N 页」**，前面再拼下载进度（`已下载 3/12 话`） |
| 下载断后重连，按进度重新下载 | 进度 = 磁盘上已落地的文件；续传时重算「缺哪些」，只补缺的（跳过已存在的）。单张图失败重试 `download.retries` 次，仍失败就只把那一话标 error，整本继续；下次点「继续下载」只补这一话 |
| 下载地址写进配置文件 | `config.yaml` 的 `download.dir`（默认 `~/.jmreader/downloads`），支持 `~` 与相对路径（相对 `~/.jmreader`） |

## 2. 数据放哪

- `data/app.db`（用户数据，`clear_cache` 不碰）新增两张表：
  - `download_album(album_id PK, title, cover_url, total, done, state, error, added_at, updated_at)`
    - `state`：`queued` / `running` / `paused` / `done` / `error`
  - `download_chapter(PK (album_id, photo_id), index_no, title, state, total, done, updated_at)`（跟 `history` 一个规矩：photo_id 全站唯一只是图源的约定，不当本地表主键）
    - `state`：`queued` / `running` / `done` / `error`
    - 这张表同时是 **`photo_id → album_id` 的映射**：`get_chapter` 靠它判断「这一话有离线副本」，阅读器读下载目录里的图。
- 磁盘：`<download.dir>/<album_id>/<photo_id>/<文件名>`（离线副本，永不被缓存清理动到）。
- **进度不额外记张数**：文件在磁盘上就是进度。`done` 是"已完成的张数"，从磁盘数出来的（显示用）。

## 3. 图片服务：两个根

原来图片服务只服务 `cache/`。现在加一个 `/downloads/` 前缀映射到 `download.dir`：

```
/images/<photo_id>/<name>              → cache/images/...      （在线随手下的缓存）
/downloads/<album_id>/<photo_id>/<name> → download.dir/...      （离线副本）
```

`get_chapter(photo_id)`：这一话在 `download_chapter` 里且文件齐 → 返回 `/downloads/...` 的地址；否则维持原样（`/images/...`，缺的照旧后台补）。阅读器不用改。

## 4. 接口（`backend/api.py` → `pywebview.d.ts`）

| 接口 | 参数 | 返回 |
|---|---|---|
| `start_download` | `album_id, title, cover_url, chapters` | 任务对象（`chapters` 是详情页手里那份 `[{photo_id,index,title}]`，省一次网络请求） |
| `get_downloads` | — | `[任务 + read 字段]`，按 `updated_at` 倒序 |
| `get_download` | `album_id` | 任务对象 / `None`（详情页按钮认状态用） |
| `pause_download` | `album_id` | 任务对象 |
| `resume_download` | `album_id` | 任务对象（只补缺的） |
| `remove_download` | `album_id, delete_files=False` | `{removed: bool, files: int}` |

任务对象：
`{album_id, title, cover_url, state, error, total, done, images_done, images_total,
  read: {photo_id, page_index, title} | None, running, added_at, updated_at}`

`read` 是**现拼**的（同一个 `history` 表，跟「最近阅读」一个口径）—— 这就是用户说的「进度和最近阅读里的一样」。

## 5. 断点续传 / 重连

- 一次下载 = 一个 daemon 线程，逐话串行；一话内部用 `download.workers` 并发下张。
- 每张图先写 `.part<后缀>` 再 rename（沿用原来那套）；**失败只删这张的 `.part`，已下好的图保留**。
- 软暂停：`threading.Event`（`pause_download` 置位，线程在话与话之间、张与张之间检查）。
- **开窗自动续传**：`API.__init__` 里把 `state in (queued, running)` 的重新入队（`running` = 上次被关窗打死），延迟几秒再开跑，别跟首屏抢带宽；`config.yaml` 的 `download.auto_resume=false` 可关。
- 关窗即停（daemon 线程），下次开窗接着下 —— 不重头。

## 6. 前端

- 导航：`{ path: '/downloads', label: '我的下载', icon: download, activeIcon: downloadOn }`。
- 详情页：`.detail-actions` 里 `继续阅读`（主按钮，flex:1）+ `下载`（次级按钮）；按钮标签随状态走：
  `下载` → `下载中 3/12` → `继续下载`（暂停 / 出错 / 断了）→ `已下载`（点了就重新校验一遍缺图）。
- `#/downloads`：卡片网格，副标题 `已下载 3/12 话 · 读到第 5 页`；卡片角上 `暂停 / 继续`、`删除`；
  有任务在跑时 1.5s 轮询一次（`onUnmount` 里停表）；空状态引导去热门。

## 7. 缓存清理的红线

`cleanup_cache` 只碰 `cache/`；离线副本在 `download.dir` 里，**永远不删**。
反过来：下载过的章节，`cache/images/<photo_id>` 那份留着也无所谓（阅读走的是下载目录）。

## 8. 设置页

`下载与缓存` 组加：`download.dir`（文本）、`download.retries`（数字）、`download.auto_resume`（开关），
`download.workers` 保留。新增配置项照规矩同步 5 处。
