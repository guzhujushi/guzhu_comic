## 0. 一句话

安卓版**不是"重新打包一个 exe"**：壳换掉（pywebview → AndroidX WebView）、桥换掉（`js_api` → 本地 HTTP），
跑的还是同一套 `backend/`（Python，由 Chaquopy 带进 app 进程）与同一份 `frontend/dist`。
**2026-10-15 已经全通**：模拟器上跑通了全部页面、真数据、真图（含整页图解扰）。

## 1. 逐层选型（就是结论）

| 层 | 选定 | 理由 / 代价 |
|---|---|---|
| Python 运行时 | **Chaquopy 17.1.0**（MIT，CPython 3.13.16 进 app 进程） | 唯一"能把现有 `backend/` 原样搬进来"的路。代价：轮子只到 cp313、构建机必须另装 Python 3.13 |
| UI 壳 | **AndroidX WebView**（Kotlin，`androidx.webkit`） | 前端已经写好，套一层即可；不引入 Flutter / RN 这类"另一套生态" |
| 桥 | **本地 HTTP JSON-RPC**：`POST /api` + `X-Guzhu-Token`，页面地址带 `?t=` | `js_api` 在安卓 WebView 上**根本不存在**；顺带堵上"同机任意进程能读 `127.0.0.1:47753`" |
| 页面来源 | 壳把 `assets/web` 解包到 `files/dist`，Python 起本地静态服务（47753），WebView 加载 `http://127.0.0.1:47753/?t=…` | 页面与图片**同源**，省掉 CORS 与绝对路径问题 |
| Python ↔ Android | Chaquopy 的 `java` 模块（`from java import jclass`） | 整页图解扰就靠它调 `BitmapFactory` / `Canvas`，**不加一行 Kotlin、不装轮子、不碰 NDK** |
| 图源客户端 | `curl_cffi 0.16.3`（官方 `android_24_arm64_v8a` 轮子）+ `jmcomic 2.7.9` | 图源要 TLS 指纹，`requests` 过不去；这两个轮子在 2026-10 已齐 |
| 后台下载 | **还没做**：`dataSync` 前台服务（设计已定） | Android 15 起 `dataSync` 24 小时内累计上限 6 小时，超时回调 `onTimeout()` → 必须优雅收尾 + 断点续传 |
| 存储 / 权限 | app 私有目录（`/data/user/0/cn.guzhujushi.comic/files`），**不申请任何危险权限** | 现有 `backend/paths.py` 的目录模型直接可用 |
| 网络 | 直连图源（不科学上网）；本地服务只认回环 Host | 实测：桌面直连可用（`tmp/STATUS.md` 有记录） |
| 构建 | Gradle 9.8.1 + **AGP 9.4.0** + Chaquopy 17.1.0；JDK 用 Android Studio 自带的 **JBR 25.0.3** | 系统 JDK 26 太新，Gradle 跑不动；**不挂 Kotlin 插件**（AGP 9 内置 Kotlin，再挂会硬失败） |
| 签名 | 发布密钥 `%USERPROFILE%\.guzhu\keys\guzhu-release.jks`，口令在用户环境变量 | 密钥与口令都不进仓库；见 `android/README.md` |

**版本线**：`minSdk 26` / `targetSdk 36` / `compileSdk 37` / 只出 `arm64-v8a`。
两条变体：`full`（真 `curl_cffi`，回真机）与 `ui`（x86_64 + `curl_cffi` 换成"一调就抛"的桩，只跑模拟器 —— 这个变体**永远验不了图源连通**）。

## 2. 看过的备选方案（都不选，理由一行）

| 方案 | 为什么不选 |
|---|---|
| Python 打包成 `chaquo` 之外的（BeeWare / Kivy / Termux 式自带解释器） | 要么重写 UI 层，要么体积/权限失控；Chaquopy 是唯一"几乎零改动"的 |
| 服务端渲染 / 远程后端 | 与"数据全在本机、不登录"的定位冲突 |
| `js_api` 式的本地 socket 桥 | 安卓 WebView 上要自己造轮子；HTTP 反而更简单、更好排障 |
| 用 Kotlin 重写后端逻辑 | 等于把项目重写一遍 |
| 前 端换 Flutter/RN | 同样的理由：只为"看起来更原生"付一整套生态成本 |

## 3. 难点（D1~D10，按当时"会不会卡死项目"排序）—— 现在的状态

| 编号 | 难点 | 现在 |

| D2 | 桥（`js_api` → 安卓 WebView） | ✅ **P0 已解决**（本地 HTTP + token） |
| D3 | 依赖落地与体积 | ✅ 已解决（Chaquopy 轮子齐；APK 签名版 35.4 MB） |
| D4 | 路径 / 存储 / 权限 | ✅ 已解决（`backend/paths.py` 加安卓分支，app 私有目录，零危险权限） |
| D5 | 长图渲染与内存 | ⚠️ 模拟器上没问题；真机一话 200 张图的内存没验（T4） |
| D6 | 触屏交互与布局 | ✅ 已做（手机版 UI 三项 + 导航挪顶，`@media (max-width: 760px)` 这一档，桌面不受影响） |
| D7 | 系统集成（`backend/desktop.py` 512 行） | 安卓侧整块作废（托盘 / 快捷键 / 自启都是 Windows 专属），代码留着不执行 |
| D8 | 热更新与版本 | ⚠️ 通道是同一份；"壳内 dist vs 覆盖层"在安卓上还没定策 |
| D9 | 构建与调试 | ✅ 已解决（`scripts/sync_android.ps1` + `scripts/build_android.ps1`，JDK 用 JBR） |
| D10 | 合规与分发（Play 上架 / 国内备案） | 不解决 —— 只自用 / 私下分发，不上架 |

## 4. 三种"环境"别混（2026-10-14 实测）

| 环境 | 要什么 | 结论 |
|---|---|---|
| 构建环境（PC 侧） | Android SDK + JDK（用 Android Studio 的 JBR）+ 另装的 **Python 3.13** | 已装齐；`local.properties` 由 AS 首开生成 |
| 连接 / 调试通道 | **`adb` 就够** —— 不需要 `sshd`、不需要 root、手机上不装任何东西 | 打开"USB 调试"即可；`adb reverse` 还能把 PC 的端口导进设备（调试用） |
| 运行设备 | 能装 APK 的安卓设备（arm64） | **不需要买设备**：x86_64 模拟器自带 ARM 翻译层，arm64 的 `full` 包能装能跑（`libndk_translation.so`，`abilist=x86_64,arm64-v8a`） |

**本机 USB 实测（2026-10-15）**：当时插着的是 HUAWEI Mate 80 Pro（`SGT-AL50`），Host 侧只报 `HDC Device`
（华为私有协议，不是 ADB 端点），MTP 根目录也没有 AOSP 那份 `Android/` 目录 → 当时判为"装不了 APK"。
**用户 2026-10-15 反馈：鸿蒙可以安装并使用，没问题** —— 以用户实测为准（能装说明那台设备的系统带 AOSP 兼容层；
纯血鸿蒙 HarmonyOS 5/6 NEXT 系通常不吃 APK）。详见 `tmp/安卓真机连接与调试操作手册.md`。

## 5. 依赖探针实测（设备上真跑出来的）

跑法：`adb shell am start -n cn.guzhujushi.comic/cn.guzhujushi.comic.MainActivity --ez guzhu.probe true`
（探针在 `android/app/src/main/python/guzhu_probe.py`，**不在正常启动路径上**），结果打 logcat `python.stdout`。

| 步 | 验什么 | 结果 |
|---|---|---|
| 1~2 | Python 起得来 / `cffi` import | ✅ 3.13.16 · cffi 1.17.1（**C ABI 那关过了**） |
| 3~4 | `curl_cffi` 载入 / `impersonate="chrome"` 的 HTTPS | ✅ 0.16.3（1.4s）· HTTP 200 |
| 5~6 | jmcomic 建客户端 / 拉真专辑详情 | ✅ 真拉 `/setting`（域名自动更新）· 真作品 `422866` |
| 7~8 | 取一话图列表 / 真下一张图 | ✅ 218,914 B（RIFF/WEBP） |
| 9 | Pillow 解 WebP | ❌ **Chaquopy 的 Pillow 没编 webp** → 这条曾经被我误判成"对本 app 零影响"，实际是 P1 的根因（下载器每张图都过 PIL） |
| 10 | （保留位） | —— |
| 11 | **系统解码器解扰真图**（P1 后新增） | ✅ `num=10`，218,914 B → 307,042 B，0.4s；与桌面解扰逐像素平均差 1.71（vs 不解扰 85.06） |

**T1（curl_cffi 装得上 + 连得上图源）、T1-b（cffi × curl_cffi 的 C ABI）、T2（jmcomic 起得来）已关闭** —— 零设备、零成本。
剩下只有真机才算数的 **T3~T6**：长图渲染上限 / 一话 200 张图内存 / 后台下载保活 / 毛玻璃掉帧。
