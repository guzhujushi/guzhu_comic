## 决策记录

- **2026-10-15（第三轮·用户拍板口径）**：**① 热更节奏改成"攒够再推"** —— 用户明确：可以热更，但每次要
  **改动到一定程度**再推；只有 0day、或者通道上那份本身是坏的（比如 10-15 那次推上去的是坏的 P0 版）才立刻重发。
  频繁推会让人反复看到「有新版前端」提示，回滚面也更大。
  **② 防社死的边界** —— 一键防社死 = 盖住整窗（**底必须不透明**：毛玻璃窗下 `--bg` 是半透明的，沿用它就露馅）
  + 停自动滚屏 + 收浮层 + 落一次进度；盖住期间吞掉其它键（免得遮罩底下还在翻页 / 换章）。
  **静音没有对象**（全项目无音频），**藏窗口**是 Windows 注册的 `Ctrl+Alt+G`（前端碰不到 Win32）——
  面板里写明怎么开，不假装前端能办到。
  **手机侧的口径（用户 2026-10-15 拍）**：手机上**不做快捷键面板**（没键盘，做了也没人能用），
  改为在阅读工具条加一颗「遮罩」按钮 —— 同一个 `togglePanic()`，只在 `@media (hover: none)` 下显示，
  桌面上仍旧只有 `P`（不加重复入口）。
  **③ 联想的数据源口径** —— 只吃本机数据（`search_log` + 收藏 / 看过标题），**不抓图源的联想接口**；
  冷启动是空的是已知天花板，不是 bug。
  **④ 触屏手势的三条硬规矩** —— 只有中间那块算双击（左右 30% 是翻页区，双击放大跟翻页会打架）；
  滑完浏览器补的那一下 `click` 不算数（`swipedAt` 挡 500ms，否则一次滑动翻两页）；
  斜着划拉 / 划太短都不算横滑（横向 ≥46px 且 ≥纵向 1.4 倍）。**长按存图要动壳 → 挂起。**
- **2026-10-15（第三轮）**：**破图自愈的口径** —— ① 防缓存参数必须**接着**原有 query 拼（`&r=`）：带 token 的图片 URL 上
  再起一个 `?` 会让服务端把 token 解析成 `TOKEN?r=1` → **每次重试都 403**（用户报的「安卓上网络一抖几张就空着、
  整本下完也不出图」根因就在这儿）；② 重试分两档（2 秒 ×30 → 15 秒 ×20），页面在后台不空转、回前台补一次；
  ③ 破图留**虚线占位**（`img[data-broken]`），不再留一条看不出来的缝；④ 顶栏加**手动刷新**（重拉本话、原地换图、
  保留页码与滚动位置）；⑤ 还有破图时每 5 秒看一眼 `get_download`，整本从「在下」变「下完」就**重新拉一次本话** ——
  必须重拉、不能只重设 `src`：整本落在 `download.dir`（`/downloads/…`），阅读器手里那批是 `/images/…`，
  不重新问后端就永远指着没写过的缓存文件。
- **2026-10-15（第三轮）**：**搜索页折叠** —— 一次结果超过 12 部就先铺 12 张 + 一颗「展开其余 N 部」；
  展开是**追加**（不重建：封面不重下、滚动位置不跳）；折叠状态**不记忆**（返回是「按地址栏重搜一遍」，仍旧折叠）。
